# AL 下游評分協定 v2（`al-downstream-v2`）

> **誠實標籤**：這份協定是**事後**訂的，不是預先註冊。§20–§23 已經看到「讀出、剪枝門檻、訓練量」三者都能翻轉結論，所以協定的價值在於**從現在起固定**、讓後續量測不能繼續挑 regime；它不能回溯地把先前那些結果變成預先承諾的檢定。

實作：`scripts/al_downstream_protocol.py`（常數寫死，不從命令列給）。測試：`tests/test_al_downstream_protocol.py`。

## 協定內容

| 項目        | 固定值                                                                 | 理由                                                                            |
| ----------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 讀出        | `potential`（膜電位）                                                  | §20：脈衝次數在同權重下 0.0、膜電位 1.0，排序能力全在讀出                       |
| 任務族      | `hard`：cue token + 噪聲位，全部共用一個 `shared` 位                   | 有干擾，才測得到「學得對不對」                                                  |
| regime 矩陣 | epochs ∈ {1, 5}                                                        | 兩個都跑、**兩個都報**，不允許挑                                                |
| 難度校準    | 固定階梯 `(48,3) (96,3) (96,2) (144,2) (144,1)` × lr 格點 `0.005…0.05` | 取第一個讓**中性臂** top-1 落在 [0.30, 0.70] 的組合；校準不到 → `uninformative` |
| 種子        | 12 個固定（11, 23, 37, 41, 53, 67, 79, 83, 97, 101, 113, 127）         | 校準另用 3 個，與評估分開                                                       |
| 控制組      | `shuffled`：**同一組增益**打亂順序                                     | 分離「平均增益」與「時序」                                                      |
| 主指標      | **訓練集** margin（正確 − 最強對手，膜電位）                           | 連續值，不受脈衝量化影響；v11 量到 held-out 對所有臂都是亂猜（見下文）          |
| 共同指標    | top-1 命中率                                                           | margin 升而 top-1 降**不算贏**                                                  |
| 增益匹配    | 三臂平均增益差 ≤ 0.05，否則 `gain-not-matched`                         | 比較才有意義                                                                    |

## 整體判詞

- `insufficient-informative-regimes`：可下結論的 regime < 2；
- `mechanism-benefit-consistent`：全部可下結論的 regime 都是
  `phase-beats-matched-mean`；
- `no-mechanism-benefit-consistent`：全部都沒贏過 neutral；
- `regime-dependent-no-claim`：方向不一致。

## 協定修訂紀錄

**v1 → v2**：v1 只校準 lr（任務固定 48/3）。結果 ep5 在**任何**
lr 都停在 0.979（lr
0.005–0.05 全同）——5 輪訓練下這個場景結構上太容易，lr 不是瓶頸。所以 v2 把「難度」也變成可校準維度，並用固定階梯（不是逐格硬調），同時把校準不到的 regime 明確標成
`uninformative` 而不是硬跑。

## v2 執行結果（2026-11-07）

| regime   | 校準                                  | neutral          | phase                | shuffled         | 判詞                       |
| -------- | ------------------------------------- | ---------------- | -------------------- | ---------------- | -------------------------- |
| epochs 1 | 48 候選 / 3 位、lr 0.03（中性 0.507） | +0.02431 / 0.502 | **−0.03378** / 0.481 | −0.03308 / 0.483 | `no-downstream-difference` |
| epochs 5 | 96 候選 / 2 位、lr 0.03（中性 0.465） | +0.01020 / 0.443 | **+0.34545 / 1.000** | +0.05706 / 0.668 | `phase-beats-matched-mean` |

**整體判詞：`regime-dependent-no-claim`。**

兩個可下結論的 regime 方向相反，而且都不是雜訊等級的差距：

- 一次性學習（1 epoch）：相位調制**有害**，margin 由正翻負；
- 五輪學習（5 epochs）：相位調制**大幅有益**（top-1 0.443 →
  1.000），而且贏過同增益打亂的 0.668——這是目前唯一一次「時序本身有貢獻」的量測。

## 因此能說與不能說

**能說**：在這支 LIF 模型上，調制的效果**取決於訓練體制**；任何單一 regime 的結果都不足以回答「機制有沒有用」。協定把這件事固定下來，並要求兩個 regime 一起報。

**不能說**：

- 不能說「相位調制有效」（ep1 反例）；
- 不能說「相位調制無效」（ep5 反例）；
- 不能說「時序沒有意義」（ep5 的 phase 0.345 > shuffled 0.057）；
- 也不能把 ep5 的結果推廣到別的任務、別的超參數或別的模型。

## 下一步（協定之內）

要讓結論從 `regime-dependent` 走向可宣告，需要的是**第三個 regime**（例如 epochs
3 或 10）與**第二個任務族**（不同干擾結構），而不是再調整現有兩格。若多個 regime 與多個任務族方向一致，才構成可宣告的機制結論；否則就維持「條件相依」。

## 協定修訂紀錄（續）

**v2 → v3**：v2 只有兩個 regime、一個任務族，結論 `regime-dependent-no-claim`
但無法區分「regime 本身」與「任務族」。v3 的做法是**增加獨立維度**，不是再調參數：

- regime 矩陣擴成 epochs ∈ {1, 3, 5}；
- 任務族擴成兩個：`hard`（全體共用噪聲位）與
  `many_to_one`（兩個 cue 共用同一個 target，干擾真的存在但答案仍可學）；
- 每個（任務族 × regime）各自沿固定階梯校準到中性臂 top-1 ∈ [0.30, 0.70]。

中途試過兩個結構但被否決，理由也留在這裡：區塊干擾（`block`）在 ep3/ep5 全部飽和到 1.000；重疊 cue（`overlap`）因為每 cue 仍有專屬 token，一律 1.000。兩者都不是「更難」，只是「更吵」。

六格全部校準成功（沒有 `uninformative`）：

| ----------- | ------ | ---------------- | -------------------- | ---------------- | -------------------------- |
| hard        | ep1    | +0.02431 / 0.502 | −0.03378 / 0.481     | −0.03308 / 0.483 | `no-downstream-difference` |
| hard        | ep3    | −0.01458 / 0.443 | **+0.21722 / 1.000** | −0.01671 / 0.500 | `phase-beats-matched-mean` |
| hard        | ep5    | +0.01020 / 0.443 | **+0.34545 / 1.000** | +0.05706 / 0.668 | `phase-beats-matched-mean` |
| many_to_one | ep1    | +0.01814 / 0.486 | −0.07006 / 0.142     | −0.07942 / 0.123 | `no-downstream-difference` |
| many_to_one | ep3    | +0.00708 / 0.479 | **+0.01112 / 0.479** | +0.00572 / 0.424 | `phase-beats-matched-mean` |
| many_to_one | ep5    | +0.01492 / 0.479 | **+0.02316 / 0.479** | +0.01394 / 0.477 | `phase-beats-matched-mean` |

**整體判詞仍是
`regime-dependent-no-claim`**（規則要求全部同向才算宣告），但這次模式不再混亂：方向**單調取決於訓練量**，且**兩個任務族一致**——

- **1 epoch：調制有害**（hard −0.034 vs +0.024；many_to_one top-1 0.142 vs
  0.486，差很大）；
- **3、5 epochs：調制有益**（hard top-1 0.443 →
  1.000；many_to_one 同為 0.479 但 margin 較高）。

`phase` 勝過 `shuffled` 的幅度則不穩定：hard ep3/ep5 很大（0.217 vs
−0.017、0.345 vs 0.057），many_to_one 只有 0.011 vs 0.006、0.023 vs
0.014——**時序的貢獻在小干擾場景裡很薄**。

## 現在能說的一句話

在這支 LIF 模型上，**調制的效果正負由「基線訓練到什麼程度」決定**：基線還沒學會時，調制讓它學更慢、更差；基線學會之後，調制讓它學得更準（hard 族 top-1
0.443 → 1.000）。任務族的干擾結構不改變這個方向，只改變幅度。

## 仍然不能說

- 不能說「相位調制有效」——ep1 兩族都是反例；
- 不能把 ep3/ep5 的幅度當成普遍效果——many_to_one 的 margin 差距只有 hard 的 1/20；
- 不能說機制在別的模型或真實語料上也如此——這裡全是合成關聯任務。

## v4：修儀器（候選 label 不能由 pair 索引拼出來）

v3 的 `_evaluate` 用 `out.get(f"t{j:02d}") for j in range(len(pairs)) if j != i`
建對手集合。在一對一任務裡索引剛好等於 label；在
`many_to_one`（48 個 pair、24 個 label）裡就壞掉：

- 索引 ≥ 24 的 pair 拼出 `t24…t47`，這些 label 不存在 → 對手集合**空**
  → 直接判 miss；
- 索引 < 24 的 pair 的另一半（同 label）從來沒被排除，真要比到也是同分。

結果是命中率**被硬性截在 0.5**，且半數 pair 的 margin 被寫成 0.0。實測：同一組權重上
`many_to_one` 中性臂 lr 0.03 舊寫法 0.486、新寫法 **0.972**。**v3 的
`many_to_one`
全部數字作廢**（校準也因此落在錯的 lr 上：看起來「中段」其實是天花板被削掉一半）。

修法：候選集由任務的目標 label 集（去重）決定，同 label 不得當自己的對手；診斷腳本
`al_c_learn_trace.py` 改為共用同一個 `_score`，避免兩套算法再度分岔。

校準種子 (11,
23, 37) 與評估種子（12 個）**重疊**，難度選擇與評估共用 3 個種子。這會讓落在 [0.30,

## 判詞詞彙修訂：把「明顯更差」叫出來（同一份 v4 資料，重新標記）

v4 的判詞只有「贏」與「沒差」兩種結局，於是 `many_to_one` ep3／ep5 的
`−0.0865／0.194` 與 `−0.1177／0.266`（中性臂
`−0.0245／0.309`、`−0.0294／0.330`）被寫成
`no-downstream-difference`。那是**把負結果記成空白**：phase 不是沒差，是兩項指標都明顯更差，而且多數種子上同時輸給兩個臂。

新增判詞
`phase-loses-to-matched-mean`，條件與「贏」對稱：margin 與 top-1 都變差、赢 shuffled 的差距也為負、且超過種子散佈、多數種子同時輸給 neutral 與 shuffled。整體判詞多一個
`mechanism-harm-consistent`（所有可下結論的格都是負向）；混在
`no-mechanism-benefit-consistent` 的情況則保留原判詞。

重跑（資料與 v4 相同，只有標記改變）：

| 任務族      | regime   | 判詞（修訂後）                                 |
| ----------- | -------- | ---------------------------------------------- |
| hard        | ep1      | `no-downstream-difference`（缺額在種子散佈內） |
| hard        | ep3、ep5 | `phase-beats-matched-mean`                     |
| many_to_one | ep1      | `uninformative`                                |
| many_to_one | ep3、ep5 | **`phase-loses-to-matched-mean`**              |

整體 `regime-dependent-no-claim`，但現在是**兩個方向都有名字的反向結果**：`hard`
在後期訓練受益，`many_to_one`
在同樣的訓練量下受害。這比「一邊有益、另一邊沒差」更精確，也更難用「大概是雜訊」帶過。

## v5：校準種子與評估種子互斥

v3 起校準用
`(11, 23, 37)`，而這三個也在 12 個評估種子裡。等於用評估用的種子挑難度，被校準進

修法：校準種子改成
`(211, 223, 241)`，並在模組層加斷言，重疊就直接匯入失敗；測試另外釘住這個不變量。

## v6：`epochs` 不能再同時改變「訓練量」與「調制頻率」

v1–v5 的排程都是「整段訓練走完一個週期」：`dt = period / (pairs × epochs)`。也就是說 5 輪訓練時，相位每個樣本只前進 1/5 個週期的 1/48——**訓練量變 5 倍，調制也慢 5 倍**。這兩個變數綁在同一個開關上，任何「ep3/ep5 比 ep1 好」的結果都同時有兩種解釋：訓練夠了，或者振盪慢到像一個學習率排程（前段高增益、後段低增益）。

v6 把每樣本的相位速度固定下來：每個 epoch 走完一個週期（`step_per_period=pairs`），
`epochs` 只改變訓練量。`shuffled` 控制組不變（同一組增益打亂）。

## 撤回：v5 的「hard 後期受益」是頻率混淆

v5（週期隨 epochs 拉長）量到 hard ep3 `+0.2172 / 1.000`、ep5
`+0.3455 / 1.000`，我把它寫成「基線學會之後調制讓它學得更準」。**在頻率固定之後這件事沒有了**：ep3 的 margin 從 +0.2172 掉到 −0.0125，top-1 從 1.000 掉到 0.516。

差距大到不像雜訊，方向也一致，所以解釋很直白：**之前有效的不是「時序」，而是「整段訓練只走一個慢週期」**——前段樣本拿到高增益、後段拿到低增益，等於一個前重後輕的學習率排程。學習率排程本來就會讓訓練比較穩，跟「經歷的時機」沒有關係。

v6 ep5 還剩下一個小效果，但方向相反：phase 與 shuffled
**都**贏過 neutral（margin +0.064 / +0.070 對 +0.010，top-1 0.699 /
0.714 對 0.443），而 **shuffled 還略贏 phase**。判詞因此是
`timing-does-not-matter-only-gain`：**增益的變動有用，順序沒有用**。

## v6 能說的一句話

在這支 LIF 模型、這個讀出、這兩個任務族上：**讓可塑性隨相位起伏，不比把它固定住好；起伏本身有一點用，但與相位順序無關——把同一組增益打亂反而略好。**
這是一個負結果，而且是被兩次儀器修正（候選 label、頻率）逼出來的，不是先有結論再找證據。

## v7：`epochs` 這一軸其實混了兩個變因

v6 把調制頻率固定住之後，剩下的假設是「`epochs`
只改變訓練量」。實際去查校準結果才發現：
**難度階梯是逐格校準的**，所以每一格都換了題目。

| 任務族        | ep1 校準到                 | ep3 / ep5 校準到           |
| ------------- | -------------------------- | -------------------------- |
| `hard`        | 48 pair, 3 噪聲位          | 96 pair, 2 噪聲位          |
| `many_to_one` | 48 pair, `target_group` 12 | 48 pair, `target_group` 24 |

於是 v6 報告裡「ep1 vs
ep5」的差異同時包含訓練量、題目大小與干擾強度三件事。任何跨 epoch 的句子在 v6 裡都不能用——不只是「後期受益」那一句，連「後期沒差」也不能說。

v7 的修法：**每族只校準一次**，候選組合必須讓 `EPOCHS_MATRIX` 裡**每一個**
regime 的中性臂 top-1 都落在 [0.30, 0.70]；某格若仍跑出範圍就標
`neutral-out-of-range`，而不是換一題重校。

第一次跑 v7 時 `hard`
整族變成不可判讀：同一題目的中性臂命中率隨 epoch 單調上升，而階梯從 48/3 直接跳到 96/2——前者 ep5 飽和到 1.0，後者 ep1 只有 0.24，中間沒有「ep1
≥ 0.30 且 ep5 ≤ 0.70」的窗口。補了 72/2 這一級之後窗口才出現（0.333 / 0.384 /
0.63）。這是**階梯粒度** 的問題，不是機制的問題，但如果不補，`epochs` 軸在
`hard` 上根本沒有可用資料。

## v8：均值差要是擲硬幣，就不算機制

v7 隔離變因之後，`hard` ep5 出現一個看起來像正結果的格：

| 臂       | margin   | top-1 |
| -------- | -------- | ----- |
| neutral  | +0.03276 | 0.573 |
| phase    | +0.06923 | 0.701 |
| shuffled | +0.04724 | 0.653 |

判詞 `phase-beats-matched-mean`。但逐種子看：phase 贏 neutral
**11/12**，贏 shuffled 只有 **7/12**。對 shuffled 的那點優勢是擲硬幣，不是時序。

v8 因此在協定層加一條規則：`phase-beats-matched-mean` 與
`phase-loses-to-matched-mean`
都要求在**兩個比較**上至少 10/12 個種子同向（單尾二項檢定 p≈0.019；9/12 是 0.073，不夠）。這條規則**只會撤掉判詞、不會生出判詞**，所以即使它是在看到 v7 的數字之後才加的，偏誤方向是保守的——但必須這樣標記，不能假裝它是事前註冊的。

## v9：校準停在邊界上，而且這是必然的

v8 說 `many_to_one`
ep1 差 0.001 被擋掉。往源頭查，發現不是難度問題，是**校準準則的形狀**：沿著單調的難度軸「第一個合格就採用」，合格區是一段區間，所以第一個合格點必然貼著區間的下界。實測兩族都這樣：

| 任務族        | 校準值（3 個種子） | 距下界 |
| ------------- | ------------------ | ------ |
| `many_to_one` | 0.306              | 0.006  |
| `hard`        | 0.333              | 0.033  |

兩族的餘裕都比種子噪音還小，換一批種子就會跨出去（`many_to_one`
在 12 個評估種子上是 0.299）。

v9：優先選「每個 regime 都離上下界至少
`HIT_MARGIN`=0.05」的候選，找不到才退回第一個合格者並標
`centred: False`。`many_to_one` 的階梯補一級 72 pair／`target_group`
12（同組目標、資料量多一級）。

## v10：3 個種子的掃描值系統性偏樂觀，而「確認」救不了它

候選，掃描量到 0.361，評估種子量到 0.306。補一個 8 種子的確認步驟之後，同一個題目得到三個不同的值：

| 確認 `CONFIRMATION_SEEDS` | 8      | **0.406**        |

**0.107**。確認步驟因此沒有解決問題，只是多了一個同樣不穩的估計，而且它讓校準提早接受了原本貼邊的那一級（48
pair），回到 v8 的 0.299。

逐種子離散度（v10 起寫進報告）：中性臂 `sd` 0.08–0.12、`se` ≈

## 對自己的批評

一個 session 內改了三次儀器（餘裕、確認種子、離散度欄位），每一次都是看到數字之後才動。三次都只會**撤掉**判詞或增加揭露，不會生出判詞，所以方向是保守的；但這個節奏不能繼續。下一個改動必須是事前決定的**檢定力**提升（把評估種子從 12 提到 40 左右，讓
`se` 降到 0.015），而不是再調一次門檻——否則每一次負結果都會生出新的門檻。

## v11：根問題——訓練與評估是同一批 pair

前幾輪一直在調門檻、種子數、難度階梯，但往上追一層才看到真正的地基：`_train` 用
`_pairs(task)` 訓練，`_evaluate` 也用 `_pairs(task)`
評估。**兩者是同一批 pair。** 所以報告裡的 `hit_rate` 一直是訓練集命中率。

直接量給看（`neutral` 臂，hard 任務，48 pair）：

| 訓練輪數 | 訓練集 top-1 | 沒訓練過的 cue 上 top-1 |
| -------- | ------------ | ----------------------- |
| 1        | 0.52         | 0.062                   |
| 3        | 0.96         | 0.062                   |
| 5        | 1.00         | 0.062                   |

「沒訓練過的 cue」是
`_heldout_pairs`：同規則、cue 索引接在訓練 cue 之後、label 集不變。0.062 就是 3/48，等於亂猜。**這個 token 層模型沒有共用特徵，新 cue 的判別 token 從未出現過，學不到**——所以它只會背，不會遷移。

v11 把這個量測做進協定：每格都報
`heldout_hit_rate_mean`、`heldout_hit_rate_sd`、 `heldout_chance` 與
`heldout_at_chance`，重跑就會自己現形：

| 任務族      | ep  | 訓練集 N/P/S          | held-out N/P/S        | 亂猜  |
| ----------- | --- | --------------------- | --------------------- | ----- |
| hard        | 1   | 0.333 / 0.500 / 0.499 | 0.028 / 0.028 / 0.028 | 0.014 |
| hard        | 3   | 0.330 / 0.498 / 0.481 | 0.028 / 0.028 / 0.028 | 0.014 |
| hard        | 5   | 0.573 / 0.701 / 0.653 | 0.028 / 0.028 / 0.028 | 0.014 |
| many_to_one | 1   | 0.299 / 0.229 / 0.281 | 0.229 / 0.181 / 0.201 | 0.083 |
| many_to_one | 3   | 0.410 / 0.345 / 0.326 | 0.250 / 0.201 / 0.229 | 0.083 |
| many_to_one | 5   | 0.458 / 0.380 / 0.405 | 0.250 / 0.243 / 0.243 | 0.083 |

## 這推翻了什麼

1. **之前每一句「這樣學比較好」都只能是「記得比較快」。** 判詞講的 `margin`
   與 top-1 都是訓練集上的；機制（相位調制）就算真的有用，也只能加速背誦，不可能證明「學會」。
2. **`many_to_one` 的 held-out 高於亂猜（0.23 vs 0.083）不是遷移。**
   那一族的 cue 共用 `n0`–`n2`
   三個噪聲 token，這些 token 在訓練時各自綁過不同 target，於是 held-out
   cue 靠干擾 token 也能猜中一部分——是**偽遷移**，而且 phase 在該處（0.181–0.243）還是三個臂裡最差的。
3. **v3 的 docstring 寫「量的是 held-out 名次」是錯的**，已改成「訓練集」並註明原因；§22 的「量 held-out 檢索」、§23 的「held-out
   margin」也一併更正。

## 下一步（根修好之前不該再調門檻）

要做真正的 held-out，任務必須有**共用的判別特徵**：每個 target 對應一個 feature
token，出現在多個 cue 裡，訓練 cue 與 held-out
cue 都帶它。這樣「學會」才有地方落腳，`epochs`
才會是學習曲線而不是飽和曲線。在任務重建之前，下游判詞的任何收緊放寬都只是在量背誦速度的差別。

## v12：把 held-out 做成真的，然後發現讀出會壓平

v11 的結論是「任務沒有共用特徵，所以 held-out 只能是亂猜」。v12 造了第三族
`structured`：每個 target 一個 `feat{tXX}`
token，同一個 target 的所有 cue 都帶它，訓練與 held-out 的 cue 都帶，只差在
`cueNN` 這個從未出現的判別 token。

held-out 終於有意義了。`neutral` 臂、48 pair、單一 epoch：

| 指標   | 訓練集  | held-out |
| ------ | ------- | -------- |
| top-1  | 1.000   | 1.000    |
| margin | +0.2389 | —        |

亂猜是 0.083（12 個 target），而訓練一輪就到 1.000——**這是整個 AL 線第一次量到遷移**。

然後就撞上下一層地基：**再多訓練一輪，讀出會壓平。**

| 訓練輪數 | top-1     | margin      | 正確 label 與最強對手 |
| -------- | --------- | ----------- | --------------------- |
| 1        | 1.000     | +0.2389     | 0.6217 / 0.3791       |
| 2        | 1.000     | +0.4585     | 1.1576 / 0.6948       |
| 3        | **0.000** | **+0.0000** | 0.9545 / 0.9451       |
| 5        | **0.000** | **+0.0000** | 1.4354 / 1.4354       |

ep3 起正確 label 的電位與最強對手**恰好相等**，所以 `_score`
一律判 miss。不是「學壞了」，是所有 target 被壓成同一個電位——Hebbian 更新在這個設定下把判別性抹掉了。

因此 `structured` 這一族在協定裡是
`ladder-exhausted`：沒有任何 step／lr 能讓中性臂在 ep1／ep3／ep5 全部落在 [0.30,
0.70]。最好的一次嘗試是 192 pair／2 噪聲位／lr 0.02，得到
`{ep1: 0.667, ep3: 0.056}`——還是被 ep3 的崩塌拖出範圍。

## 這意味著什麼

下游問題現在**在任何訓練長度上都答不了**：

- `hard`／`many_to_one`：held-out 等於亂猜（或只是共用噪聲 token 的偽遷移），量到的是背誦速度；
- `structured`：held-out 真的有意義，但讀出在第二輪訓練就壓平，`epochs`
  軸沒有可用的中間點。

也就是說，卡住的不是判準、不是種子數、不是難度階梯——是**讀出在持續 Hebbian 訓練下會塌成同分**。在處理這件事之前，任何「相位調制有沒有用」的下游答案都只是在描述一個塌掉的量具。

下一個根問題很具體：`TensorSNNCore.hebbian_update`
在重複訓練下把各 target 的膜電位壓成相同值（權重正規化？成長上限？）。修它之前，`epochs > 1`
的所有格子都不該被當成學習曲線讀。

## v13：塌的是讀出，不是權重

上一輪看到 `structured`
在 ep3 起 top-1 變 0、margin 恰 0.0000，直覺是權重被壓平。去量權重：ep5 時
`featt00 → t00` 是 0.157，`shared →`
每個 target 是 0.13，判別結構還在。真正發生的事在讀出端——`potential` 是
**16 個時間步**的膜電位累積，等於在無向權重圖上做擴散：權重一強，整個連通分量在幾步內被填到同一個值。

同一批權重、同一個 cue，只換讀出：

| 訓練輪數 | `potential` 正確 label                           | `direct`（W·a）正確 label | `potential` top-1 | `direct` top-1 |
| -------- | ------------------------------------------------ | ------------------------- | ----------------- | -------------- |
| 1        | —                                                | —                         | 1.000             | 1.000          |
| 3        | 0.955 vs 最強對手 0.945（正確 label 排不進前三） | 0.334 vs 0.201            | 0.000             | 1.000          |
| 5        | 1.435 vs 1.435                                   | —                         | 0.000             | 1.000          |

所以 v13 加了 `direct` 讀出（一步
`W · a`，不做脈衝動力學），並把讀出參數一路串進
`_measure`／`calibrate_family`／`evaluate_cell`。**預設仍是
`potential`**，既有報告要能重現； `--readout direct` 等於重新基線。

## 這次的判讀

換掉會塌的讀出之後，答案沒有變好，而是變得更明確：

1. **`many_to_one`
   ep1／ep3：phase 在 12/12 個種子上同時輸給 neutral 與 shuffled**（top-1 0.184
   vs 0.408／0.274，0.399 vs
   0.535／0.464）。這是整個 AL 線第一個**種子穩健的負結果**，而且是在唯一校準得動的那一族上拿到的。
2. **ep5 的翻轉不是機制**：phase 0.689 雖然 12/12 贏 neutral，但只贏 shuffled
   5/12，被種子規則降級。三輪下來 phase 的形狀是「早期傷、晚期與打亂相同」，不是時序優勢。
3. **`hard`／`structured`
   在線性讀出下直接天花板**：每個 cue 都有自己的判別 token，只要它的邊大於 0，top-1 就贏，所以任何 lr 都是 1.000，進不了 [0.30,
   0.70]。這不是難度不夠，是任務只有「唯一 token」這一種證據——需要重疊特徵才會有中段。

## 下一個根問題（很具體）

任務需要**多個互相衝突的證據**（同一個 cue 同時帶支持與反對某 target 的 token），中段才會存在；在那之前，`hard`／`structured`
永遠只有 1.0 與 0 兩種值，而 `many_to_one`
的 0.4–0.5 是共用噪聲 token 撐出來的，不是設計出來的難度。

## v14：給任務衝突證據，命中率終於有中段

v13 的結論是「任務只有唯一 token 一種證據，所以命中率只有 1.0 與 0」。v14 造了第四族
`conflict`：cue **完全沒有專屬 token**，只由跨 target 共用的 feature 組成——

- 8 個 target、12 個 feature；
- 每個 cue 取 5 個 token：2 個是目標的支持證據（`f{t*3}`、`f{t*3+1}`），3 個按索引從池子抽；
- 每個 feature 至少對 2 個 target 有邊，所以沒有任何一條邊能單獨決定答案。

校準落在 lr 0.01，中性臂 ep1/3/5 = **0.375 / 0.483 /
0.497**（亂猜 0.125），全部在 [0.30,

## v15：「沒有差別」的解析度有多大

v14 的判詞是「沒有差別」，但那句話只有在說得出「多小的差才偵測得到」時才有意義。v15 把兩個量寫進每一格：

- **配對差**（同一個種子上 `phase − neutral`
  的均值、散佈、95% 半寬）——逐種子勝負只看方向，配對差才看得出大小；
- **MDE**（minimal detectable delta）：符號門檻要求 n 個種子裡至少
  `SIGN_TEST_MIN`
  個同向，每個種子同向的機率是 Φ(δ/σ)。所以在觀測到的 σ 上，反解出「power
  0.8 時能偵測到的最小 δ」。

解析度本身：

| σ（配對差散佈） | n=12、門檻 10/12 | n=40、門檻 26/40 |
| --------------- | ---------------- | ---------------- |
| 0.10            | **0.112**        | 0.052            |
| 0.05            | 0.056            | —                |

也就是說，12 個種子、10/12 的門檻，**偵測不到小於約 0.11 的差**——比前幾輪一直在爭的 0.05 餘裕大兩倍。之前把 0.05 的邊界當成事件在處理，是在檢定力之下的爭論。

## 讀法

1. **`conflict`
   ep1 有一個小的、統計上分得開的 top-1 增益**：+0.0556，95% 區間 [0.013,
   0.099] 不含 0。但同一格的 margin 是
   **−0.00136**，而且逐種子只贏 8/12。協定要求 margin 與 top-1
   **同向**才給正判詞，所以判「沒有差別」——這是對的：連續指標說沒有變好，命中率的增益看起來像平手被打破，不是分數被拉開。
2. **`many_to_one` 的傷害是大的**：ep1 −0.224、ep3
   −0.135，兩者都遠超 MDE（0.113／0.052），而且 12/12 同向。這不是雜訊。
3. **`many_to_one` ep5 的 +0.161 與 margin
   −0.0002 並存**：命中率上升而分數差沒動，正是「平手被打破」的形狀，不是學會了更好的表示。

所以目前的完整答案：**在一個有中段、有遷移的任務上，相位調制在 ep1 有一個小幅的 top-1 增益（+0.056，CI 不含 0），但 margin 沒有改善，之後兩輪都歸零；在背誦型任務上早期是明確的傷害。**
沒有「時序優勢」的證據。

## v16：量具本身的控制——打亂標籤

前十五版都在問「相位調制有沒有用」，卻從來沒問「這些命中率有在量學習嗎」。v16 補上控制：**同一批輸入、標籤迴圈位移一位**再訓練（權重統計與真訓練完全相同），然後用真 pair 評估。

| 任務族      | 亂猜  | 打亂標籤訓練 | 打亂標籤 held-out |
| ----------- | ----- | ------------ | ----------------- |
| hard        | 0.021 | **0.000**    | **0.000**         |
| conflict    | 0.125 | **0.000**    | **0.000**         |
| structured  | 0.083 | **0.000**    | **0.000**         |
| many_to_one | 0.042 | **0.000**    | **0.000**         |

讀法：這不是「掉到亂猜」，是**掉到亂猜以下**。位移是固定雙射，每個 cue 都把「錯誤的標籤」學得很牢，所以真標籤永遠贏不了——這正是「學到了特定對應」的簽名。若命中率其實來自輸入結構（共用 feature 的共現），換標籤不會改變分數，控制組會停在原處。

所以：0.375–0.535 這些中段是**學來的**，不是結構給的。前面所有跨臂比較量的確實是學習。

控制組也會寫進每次執行的 JSON（`controls`），和判詞一起留檔。v16 的判詞與 v15 相同（`no-mechanism-benefit-consistent`）：控制是加在量具上，不是改門檻。

## v17：增益匹配的閘門原本不可能失敗

`gain_matched` 一直是
`abs(mean(phase) − mean(neutral)) <= 0.05`。但排程每個 epoch 剛好走完一個週期，相位臂均值**實測 1.0000369**（差 3.7e-5），中性臂是 1.0——這個容差在任何情況都不會綁定。不可能失敗的閘門不是控制，只是裝飾。

v17 改成驗真正會壞的地方：

| 檢查                   | 實測                    | 失敗長什麼樣                                       |
| ---------------------- | ----------------------- | -------------------------------------------------- |
| 均值差                 | **3.7e-5**（容差 0.01） | 排程週期被改壞                                     |
| 同一組增益（multiset） | True                    | 打亂臂的「量」和相位臂不同                         |
| 順序確實不同           | True                    | `shuffled` 只是 `phase` 的複本，兩臂等於自己比自己 |

第三條尤其要緊：如果打亂種子剛好是恆等排列，`shuffled` 會與 `phase`
逐位相同，比較就變成自己比自己、且永遠打平——那種「沒有差別」是假的。

## 順帶暴露的混淆：散佈不是時序

相位臂的增益實測 **0.4–1.6、sd 0.4762**。所以 `phase` 對 `neutral`
的比較同時混了兩件事：

- 每步增益有大小（散佈）；
- 增益的**順序**（時序）。

只有 `phase` 對 `shuffled`
才隔離時序——兩臂同一組增益、只換順序。用這個乾淨的比較重讀：

| 族          | ep  | phase > shuffled | 讀法                   |
| ----------- | --- | ---------------- | ---------------------- |
| conflict    | 1   | 25/40            | 沒有時序好處           |
| conflict    | 3   | 14/40            | 沒有時序好處           |
| conflict    | 5   | 6/40             | 沒有時序好處           |
| many_to_one | 1   | 0/40             | **時序比隨機順序更糟** |
| many_to_one | 5   | 5/12             | 沒有時序好處           |

兩件事因此清楚分開：

1. **`many_to_one` 的傷害不是散佈造成的。**
   打亂臂有同樣的 0.4–1.6 散佈，phase 仍 12/12 輸（ep1/ep3）——壞的是**順序**，不是「有時大時小的增益」。
2. **`conflict` 上没有任何時序效果。**
   在唯一隔離時序的比較裡，三輪都沒有贏過隨機順序。

判詞與 v16 相同（`no-mechanism-benefit-consistent`），但理由更乾淨：不是「與中性臂沒有差別」，而是「與同散佈的隨機順序相比，相位順序沒有任何好處，在背誦型任務上還更差」。

## v18：兩個不會失敗的檢查，與一個被 margin 擋掉的 top-1 效果

### 1. `_heldout_pairs` 的洩漏檢查是空的

原本是：

```python
assert not set(id(pair) for pair in held) & set(id(pair) for pair in train)
```

`held` 與 `train` 是不同時間建立的物件，`id()`
永遠不會相等，所以這道斷言**不可能失敗**。它看起來像在防洩漏，實際上什麼都沒檢查。改成比**內容**（cue 的 tuple 集合），並把
`conflict` 這條走 `features` 分支、原本直接
`return`（根本沒經過斷言）的路徑也接上檢查。

實測五族皆 0 條重疊（easy/hard 16、48 條；conflict/structured/many_to_one
48–96 條），所以**沒有洩漏**——但這現在是被檢查過的，不是被假設的。

### 2. held-out「在亂猜」的門檻沒有來源

原本
`heldout_at_chance = 所有臂 heldout ≤ 2 / len(targets)`：係數 2 沒有出處，也不看 held-out 有幾條。改成二項散佈上界
`p + 2·√(p(1−p)/m)`（m = held-out pair 數）：

| 族          | 亂猜 p | 舊門檻 2p | 新上界    | neutral / phase / shuffled |
| ----------- | ------ | --------- | --------- | -------------------------- |
| conflict    | 0.125  | 0.250     | **0.193** | 0.361 / 0.420 / 0.333      |
| many_to_one | 0.042  | 0.083     | **0.099** | 0.056 / 0.118 / 0.125      |

結論沒變（held-out 到處都高於亂猜），但有一件事現在看得出來：`many_to_one` 的
**neutral臂在亂猜**（0.056 ≤
0.099），而 phase 與 shuffled 是亂猜的 2.8 倍。兩臂差別只在「增益有沒有大小」，所以這個遷移來自**變動的增益**，不是時序。這是一個觀察，不是判詞。

### 3. margin 不動時，top-1 的移動被寫成「沒有差別」

`_verdict` 的主閘門是 margin 對 `pstdev(neutral margin)`。在 `many_to_one`
上 margin 幾乎是平的（ep5 差 −0.0002），但 top-1 從 0.528 跳到 0.689。舊判詞把這格寫成
`no-downstream-difference`——一個 12/12 種子同向、+16 點的 top-1 效果被記成「沒差」。

補上對稱於 `margin-gain-without-hit-gain` 的判詞：

| 判詞                           | 條件                                               | 算不算機制好處                     |
| ------------------------------ | -------------------------------------------------- | ---------------------------------- |
| `hit-gain-without-margin-gain` | top-1 在 ≥ 二項門檻的種子上變好，但贏不過 shuffled | 不算（好處來自增益散佈）           |
| `hit-gain-over-both-arms`      | top-1 贏過兩個臂但 margin 沒過門檻                 | **未定**：詞彙裡沒這格，不自動歸類 |

門檻用
`_sign_test_minimum(n)`，不是「多數」：8/12 是多數，但 P(X≥8|12,0.5)=0.19。這一點當場改變了一個格：`conflict`
ep1 的 top-1 是 8/12，用多數會變成 `hit-gain-over-both-arms` （→ 整體
`regime-dependent-no-claim`），用二項門檻（12 個種子需 10）則維持
`no-downstream-difference`。

## v19：margin 閘門的尺度量出來，然後假設被推翻

v18 之後剩下的問題是：`margin_gain > pstdev(neutral margin)`
這條線到底有多嚴？我在動手前先寫下一個假設——**這條線大概落在十幾個配對標準誤上，所以幾乎不可能靠雜訊越過**。量完之後這個假設是錯的，而且錯得剛好相反：**線只落在 2.0–3.3 個配對 SE**。

| many_to_one | 1   | 0.0004    | −0.0024 | 0.0002 | **11.24** | **2.00**     | phase-loses-to-matched-mean  |
| many_to_one | 3   | 0.0005    | −0.0021 | 0.0001 | **14.64** | **3.34**     | phase-loses-to-matched-mean  |
| many_to_one | 5   | 0.0004    | −0.0002 | 0.0002 | **1.20**  | **2.08**     | hit-gain-without-margin-gain |

三個讀法：

1. **門檻是 ~2–3 SE，不是十幾個。** 12 個種子下 `pstdev(neutral)`
   只有幾個毫點的 margin 散佈，而配對 SE 更小（0.0001–0.0028）。線寬與 SE 同一個量級，所以「雜訊剛好越過線」是可能的，不是理論上的擔心。
2. **`gain/se` 與判詞方向不一致的地方是資訊，不是雜訊。** `many_to_one` ep5 的
   `gain/se = 1.20` 但
   `yardstick/se = 2.08`——差距一個多 SE、線兩個 SE，所以判詞走到
   `hit-gain-without-margin-gain`（top-1 好、margin 沒贏）。ep1/ep3 是 11–15
   SE 的**負向**差距。
3. **線的寬度隨族變**（conflict 0.0034–0.0064、m2o
   0.0004–0.0005），所以「同一個門檻」在不同族上其實鬆緊不同。這一點在 v19 之前只是懷疑，現在有數字。

### 只收緊的下限：`MIN_GAIN_OVER_SE = 2.0`

既然線可以落在 1 SE 上，`_verdict` 現在除了「贏過散佈」之外還要求
`|margin_gain| ≥ MIN_GAIN_OVER_SE · paired_se`（沒有散佈或樣本不足時不套用）。這條規則**只可能把判詞從「有差」推向「沒差」**，不可能製造新的正向判詞——所以不需要重跑就能保證它不會憑空生出好處，實測也確實沒有改變任何一格：

- v20 重跑（同樣 12 種子）：**六格判詞與 v19 逐格相同**，整體仍是
  `no-mechanism-benefit-consistent`。
- 兩個方向的測試都寫了：同樣的 gain 0.10，配對差很穩時判
  `phase-beats-matched-mean`，配對差 ±0.20（SE≈0.09）時判
  `no-downstream-difference`——而這格正是**舊規則會判贏**的情況（0.10 > 散佈 0.025）。下限唯一會擋下的就是這種格。

### 另一個負結果：`hard` 與 `structured` 兩族產生 0 格

協定跑完 15 格只有 6 格有 `cell`；`hard`（`DEFAULT_TASK`）與 `structured`
三輪全是
`informative: False`、`reason: ladder-exhausted`。原因是這些族在 5 個 epoch 內階梯就已收斂完，沒有可比較的中段/遷移。這不是判詞「沒差」，而是**這兩個族在這組排程下沒有量到東西**——把它們算進「多數」會讓結論看起來比實際更有根據。真正被量到的只有
`conflict` 與 `many_to_one`。

## v21：`hard` 的「中段」是讀出的產物

v19/v20 把 15 格裡 9 格沒有 `cell` 的事寫成
`ladder-exhausted`。查下去發現那不是階梯不夠長，而是**那幾族根本沒有中段**——而且原因是過去一個已經被否掉的讀出。

同一個 `hard` 任務（48 對、3 個噪聲位、所有 cue 共用
`shared`），換讀出量中性臂 ep1：

| 讀出        | lr 0.005（48 對） | lr 0.05（48 對） | lr 0.005（144 對） | lr 0.05（144 對） |
| ----------- | ----------------- | ---------------- | ------------------ | ----------------- |
| `potential` | 0.042             | 1.000            | 0.000              | 1.000             |
| `direct`    | **1.000**         | **1.000**        | **1.000**          | **1.000**         |

`direct` 下每一級、每個學習率都是 1.0。原因是任務結構：`_pairs`
給每個 cue 一個**專屬 token**
（`cue00`、`cue01`…），48 對就是 48 個互斥 target，一次 Hebbian 就把每條邊記住，top-1 直接頂到天花板。把階梯往上加（48→144 對、3→1 個噪聲位）沒用——加的是「更多互斥的 cue」，不是「更多干擾」。

而 `potential`
下的「中段」只存在於很窄的 lr 窗口：低 lr 塌到 0.0–0.042、高 lr 打滿 1.0。v7/v8 記錄的
`hard` 中段（0.573 / 0.701 / 0.653）是在 `potential`
下量的，那就是讀出被換掉的原因（見 v13：`potential`
會在無向權重圖上擴散，把答案填平）。**讀出換成誠實的 `direct` 之後， `hard`
的中段也一起消失了。**

所以「六格」這個說法要改：可下結論的格只來自
`conflict`（cue 沒有專屬 token，靠多數證據）與
`many_to_one`（多個 cue 共用 target，干擾是真的）兩族。`easy` / `hard`
結構上在頂端， `structured`
是 ep1/ep3 中段、ep5 飽和到 0.806——三族都**沒量到**，不是「沒差」。

### 失敗理由要分得開

`_exhaustion_reason()` 只看**第一個量到的 epoch**（`_measure`
一跑出範圍就停，後面本來就沒量）：

| 理由               | 條件                                  | 加階梯有用嗎 | 實測族       |
| ------------------ | ------------------------------------- | ------------ | ------------ |
| `task-at-ceiling`  | 每一級 ep1 都 ≥ 0.70                  | 沒用         | `hard`       |
| `task-at-floor`    | 每一級 ep1 都 ≤ 0.30                  | 沒用         | （本次無）   |
| `ladder-exhausted` | 至少一級 ep1 在中段，但撐不到 ep3/ep5 | 可能有用     | `structured` |

第一次接上去時，`hard` 還是被標成 `ladder-exhausted`：`_exhaustion_reason`
拿字串鍵 `"1"` 去讀 `calibrate_family` 回傳的
**int 鍵**，讀不到就退回預設理由。測試沒抓到，因為測試資料用字串鍵（那是 JSON 裡的樣子，不是記憶體裡的樣子）。現在兩種鍵都讀，並有一個測試專門釘 int 鍵。

### 報告的版本字串卡在 v16

`PROTOCOL_VERSION` 從 `al-downstream-v16`
之後就沒再改，所以 v17、v18、v19、v20 的報告 JSON 裡全部自稱
`v16`——檔名說 v20、內容說 v16，報告說不出自己是哪一版量具產生的。v21 起改為
`al-downstream-v21`，並且把「改量具就要同步這一條」寫在常數旁邊。

v21 重跑（`--readout direct`，12 個種子）：六格判詞與 v19/v20 逐格相同，整體仍
`no-mechanism-benefit-consistent`；差別只有 `hard` 的 `reason` 從
`ladder-exhausted` 變成 `task-at-ceiling`，以及報告裡的版本字串終於對得上。

### v22：量不到的族要具名，不能只是「沒有 cell」

v21 的報告裡，`hard`／`structured` 的狀態是「這一格沒有
`cell`」——在 JSON上看起來跟「量過、沒差」一模一樣，只有去讀 `reason`
才分得出來。這種差別靠人記住就會忘記，於是 v22 把它變成資料結構：

- `UNMEASURED_FAMILIES`：具名登記「結構上量不到中段」的族與原因。目前兩條——
  `hard`（每 cue 有專屬 token，ep1 即 1.000；中段只存在於已廢棄的 `potential`
  讀出）、 `structured`（ep1 完全遷移、ep3 起電位壓成同分 → 讀出崩成 0）。
- 報告新增 `unmeasured`（族 → 原因）與
  `unregistered_unmeasured`（有量不到、但沒登記的族）。
- `overall_verdict` 先看
  `unregistered`：只要有**沒登記**的族量不到，整體判詞一律是
  `unmeasured-unregistered`，不得給出「沒有機制好處」這種結論。理由很直接——少一族的證據卻照樣下結論，就是拿沒量到的東西冒充量到的。
- `scripts/al_unmeasured_budget.txt`
  是棘輪：登記數只能減不能增（目前 2）。要新增一族又量不到，必須同時上調預算並寫出結構原因，`tests/test_al_downstream_protocol.py`
  會釘住兩者相等。

v22 重跑（`--readout direct`，12 個種子）：12 格逐格與 v21 相同（`informative`
與判詞全等），整體仍
`no-mechanism-benefit-consistent`，`unregistered_unmeasured`
為空。也就是說這一輪改的是「量不到有沒有被說出來」，不是判詞。
