## 1. 已量到的階梯（可重跑）

`./.venv/bin/python scripts/al_ladder.py --report data/intelligence_reports/al_ladder.json`

四個候選同資訊、同目標：`al`（生產的 `core.life.al_arousal`
閉式解，零訓練）、`mlp`（numpy 3→16→16→2，訓練 dt∈[0.5, 60] s，測 dt∈[90, 600]
s）、`copy`（原值不變，控制組）、`const`（永遠回基線，最便宜的預測器）、`forgery`（記住最後一個值加噪聲，不看經過時間）。

| 階          | 在工作量什麼            | al      | mlp         | copy    | const   | 判定                                           |
| ----------- | ----------------------- | ------- | ----------- | ------- | ------- | ---------------------------------------------- |
| r1 半群     | 一次推進 vs 分兩次      | 2.2e-16 | 3.2e-01     | 0       | 0       | **sound-not-evidence**                         |
| r2 取樣率   | 600 s 一步 vs 600 步    | 3.3e-15 | 8.7e-01     | 0       | 0       | **sound-not-evidence**                         |
| r3 吸引子   | 無事件久置 → 基線且單調 | 3.4e-05 | 4.5e-01     | 7.0e-01 | 0       | al-wins                                        |
| r4 內插 dt  | dt 在訓練範圍內         | 0       | 2.0e-02     | 9.2e-02 | 2.4e-01 | al-wins                                        |
| r5 外推 dt  | **dt 超出訓練範圍**     | **0**   | **1.4e-01** | 2.7e-01 | 1.2e-01 | **al-wins**                                    |
| r6 重啟     | 落盤、隔 300 s 重開     | 0       | —           | 2.4e-01 | —       | al-wins                                        |
| r7 時鐘攻擊 | 倒退／前跳，會存疑嗎    | —       | —           | —       | —       | **doubt-works**（倒退 1/1、前跳 1/1、誤報 0%） |

三件要說清楚的事：

1. **r1、r2 不是證據。**
   閉式解對切分時間不變，但「什麼都不做」也不變（`copy`、`const`
   都是 0）。所以這兩階只證明規則健全，判定自動降級為
   `sound-not-evidence`；一個連控制組都通過的測試，不能拿來宣稱生命。
2. **r5 是真正分得開的一階。**
   同資訊、同目標下，設計的規則在沒見過的 dt 上誤差 0，學出來的 0.14。這證明的正是 review
   §9.5 說的「時態買到的是效率與外推，不是新能力」——它是**好的動態先驗**，不是生命。
3. **r7 現在可評分了。** `ClockGuard` 用 `time.monotonic()`
   當不可偽造的參考，wall-clock 倒退或前跳都會被標記（實測 1/1、1/1，誠實樣本誤報 0%）。注意：**同時偽造兩個來源仍偵測不到**——沒有第三個時間源，這是系統邊界（review
   §11.6）。0），前跳就整段衰減，模組沒有任何「現在應該是幾點」的估計，因此沒有東西可以存疑。`None`
   不能寫成 0 分通過。

### 1.1 這份階梯的邊界

- 只量一個欄位（`emotion.arousal`）。`effective`（參數層濾波器組）仍未接線，快照上是
  `None`（D11 誠實標記）。
- 沒有 GRU／neural
  ODE 基線。MLP 是最弱的學習基線；帶 dt 的循環模型會強得多，所以 r5 的 0.14 是**上界寬鬆的一方**，加進來只會讓「al-wins」更難成立、更容易被推翻——這正是應該先做的那件事。
- 只有一路時鐘，沒有多執行緒競態、沒有 NTP 跳變、沒有 DST。

## 2. 指標：三層記分卡

### 2.1 生命證據層（唯一可以拿去宣稱的）

規則：**每一階都要有 (a) 對照基線、(b) 偽造品、(c) 控制組**。控制組通過 ⇒ 該階不計分；偽造品通過 ⇒ 該階不計分。分數不是加總，是**剖面**：AL 仍然贏的最高一階，就是目前證明的上限。

| 指標            | 定義                                    | 通過門檻                               | 現況                                    |
| --------------- | --------------------------------------- | -------------------------------------- | --------------------------------------- |
| `L-truncation`  | 一次推進 vs 分 N 次的差                 | < 1e-9                                 | 過（但同時是 r1，非證據）               |
| `L-unseen-dt`   | 沒見過的 dt 區間的 MAE                  | 優於最強學習基線 10 倍                 | 過（MLP 0.14 vs 0）                     |
| `L-restart`     | 重啟後按實際經過時間的誤差              | < 1e-6                                 | 過                                      |
| `L-doubt`       | 時鐘倒退／偽造的存疑率                  | 偽造時鐘被標記 ≥ 90%                   | **通過**（倒退 1/1、前跳 1/1、誤報 0%） |
| `L-selfclock`   | 不給時鐘時對經過時間的估計誤差          | 校準（P50 誤差 < 20%）                 | **缺機制**                              |
| `L-individual`  | 同輸入、不同經歷 → 輸出差異可被歷史解釋 | 解釋變異 > 50%                         | 結構上成立，未量                        |
| `L-closed-loop` | AL 影響生成、生成回饋 AL 的雙向耦合     | 勝過只讀 AL 文字（B 組）與不接（A 組） | 只做到路由層                            |

### 2.2 系統可用性層（可以拿去用，但不能拿去宣稱）

- 任務準確率（算術／block／對話人話率）、延遲、失敗可解釋率。
- 現況：算術 653/653、block 200/200、人話 64.9%、邊界題 0/324。
- 這一層的改進**不影響**生命宣稱；把它寫進生命證據是偽造品最常見的作弊方式。

### 2.3 模型能力層（純神經，用來除錯）

- token 準確率只是除錯訊號；決策指標是逐欄位精確率與回應精確率（現況 0.08–0.25%
  / 0–2/200）。
- 這層永遠不與系統分數混算。

## 5. 專案模型現在的問題（已量測，非推測）

1. **純神經核心 0/200 不是訓練不足。** 四個槓桿都拉過：epoch 30→90 =
   0.340→0.337；資料 800→2000 = +0.022；容量 ×4 =
   0.355 且開始記憶化；只有 3dp 數值原子讓 block
   token 從 0.723 升到 0.814。**token 準確率不是可用性。**
2. **介面比模型更致命。**
   3dp 區塊在舊 tokenizer 格點上構造性為零（2633 列中 0 可表示），逐 token 誤差累乘讓整列正確率落到 5e-4。同容量 Transformer 也是 0/200。
3. **可用性早就不是模型問題。** 算術 653/653 由 `deterministic_router`
   承擔，block 200/200 由 table∪operator 承擔，SNN 貢獻 0/200。
4. **AL 只有一個欄位真正有時間。** `arousal`
   正確（閉式、半群、跨重啟）；`effective` 未接線；`advance_tick`
   無生產呼叫者；沒有時間估計與校時。
5. **生命證據目前是空的，而且不是因為方向錯，是因為還沒做機制測試。** r7 的
   `None` 是這個專案最誠實的一格。

## 6. 預期

### 6.1 還要多少工程量

| 目標                                       | 工作量                        | 說明              |
| ------------------------------------------ | ----------------------------- | ----------------- |
| 可防偽的判讀表（能回答「是不是模板」）     | 3–4 人日                      | M1                |
| 組織型弱宣稱的門檻（自己取得時間、會存疑） | 再加 6–9 人日                 | M2                |
| 公平對照與剖面（可證或可推翻）             | 再加 5–7 人日                 | M3                |
| 閉環（最接近宣稱的一步）                   | 再加 8–12 人日                | M4                |
| **合計**                                   | **22–32 人日（單人 5–7 週）** | 不含重構、不含 UI |

**不會因為工程量增加而改變的部分**：純神經核心不會變成 LLM。這不是進度問題，是有狀態系統的理論天花板（review
§9.5）：它的優勢在效率、外推、線上更新，不在新能力。要「像本地 LLM 一樣好用」，終點是**接一個真的 LM**（llama.cpp 等），AL 負責時間與狀態，而不是讓 SNN 去寫自然語言。

### 6.2 可能的智能程度

| 對象                              | 現在                            | 做完 M1–M4 的合理預期                      | 不可能達到                             |
| --------------------------------- | ------------------------------- | ------------------------------------------ | -------------------------------------- |
| 純神經核心（算術／自由文本）      | 0/200；逐欄位 0.1–0.25%         | 0–1/10，最好情況是「格式與路由稱職」2–3/10 | 任何接近 LLM 的生成                    |
| 系統（算子 + 檢索 + 模板 + 神經） | 6.41/10；算術與 format 近乎滿分 | 7–7.5/10（接真 LM 後才是這個數字）         | 無 LM 情況下的開放式對話               |
| AL（時間與狀態）                  | 一階剖面只到 r6                 | 行為上「擅長沒見過的時間間隔與缺席後連續」 | 意識、感受、或超越完整歷史基線的新能力 |

一句話：**智能程度的天花板由基礎模型決定，AL 決定的是「時間上的連續性與自主性」；把兩者混算就會得到偽智能的分數。**

### 6.3 什麼程度的數據生命

分級（本文定義，取代模糊說法）：

| 級                              | 條件                                                                 | 現況                                                        |
| ------------------------------- | -------------------------------------------------------------------- | ----------------------------------------------------------- |
| **L0 時間寫在標籤上**           | 時間是輸入文字（`Day N`、`今天很累`）                                | B 站娘化帳號的水位；也是本專案在 `--expose-dt` 介面上的水位 |
| **L1 時間作用在狀態上**         | 有欄位隨實際經過時間演化、跨重啟連續                                 | **已達**（`emotion.arousal`）                               |
| **L2 對時間有自己的估計與懷疑** | 不確定度、校時、偽造時鐘被標記                                       | 缺（r7 = `None`）                                           |
| **L3 組織型**                   | 快慢變數並存、無輸入時自我維持、經歷造成個體差異、AL 影響生成        | 部分（路由層）                                              |
| **L4 閉環**                     | AL 與 AI 互相影響，且贏過所有同資訊基線（含 GRU/neural ODE）與偽造品 | 未開始                                                      |

**結論：目前是 L1，做完 M1–M2 是 L2，做完 M4 才可能碰到 L3–L4 的邊；而 L4 的「贏」很可能只是效率與外推，不是新能力。**
因此誠實的宣稱不是「它是活的」，而是「在時間這一軸上，它做的不是模板能做的事；證據放在機制與外推，不放在主觀印象」。

### 6.4 三個需要你決定的事

1. **弱宣稱是表現型還是組織型。**
   表現型（「比較強」）目前沒有證據支持；組織型（「有自己的時間與狀態」）才是 M1–M2 在做的。
2. **「唯一算子、可稽核」與「學習^2」的取捨。**
   前者保證可審計，後者是元學習的前提，兩者直接衝突。
3. **是否接受「接真 LM + AL」作為終點。**
   若不接受，純神經核心的合理目標要下修到「格式與路由稱職」，而不是「像 LLM」。

## 7. 偽智能標準：把專案的證明責任套到生命層

專案在系統層早就有一套反偽智能紀律，只是先前沒有套到 AL 上：

| 既有機制                                                      | 位置                                 | 它防的是什麼             |
| ------------------------------------------------------------- | ------------------------------------ | ------------------------ |
| 六型分數，只有 **驗證分／實際分** 計入                        | `ai/meta/intelligence.py`            | 拿架構分、預期分冒充能力 |
| 正確答案按 provenance 分欄，只有「正確 ∧ computed」算系統產出 | `scripts/census_reply_provenance.py` | 查表答對被說成「它會」   |
| strict 計分，答錯與誠實棄權分開                               | `scripts/run_benchmarks.py`          | 「相關」冒充「正確」     |
| 及格線由外部錨點推導，不可手改                                | `INTELLIGENCE_PASS_CRITERIA.md`      | 自訂門檻後宣稱達標       |

AL 這一層原本只有能力表（`al_ladder.py`），**能力正是偽造品能模仿的東西**。所以補上兩道閘（`scripts/al_forgery.py`，可重跑）：

### 7.1 閘一：偽造品預算（forgery budget）

一個「假」不是一個模板，而是一串預算遞增的假；一階只有在**全部**都失敗時才算數：

| 偽造品        | 預算                                           | 它模仿什麼                         |
| ------------- | ---------------------------------------------- | ---------------------------------- |
| `table_noise` | 記住最後一個值＋噪聲，不讀時鐘                 | 「日誌寫了今天很累」               |
| `call_clock`  | 每呼叫一次衰減一步，不看實際經過時間           | 一天一則訊息時看起來完全正確       |
| `imitate`     | 用規則自己的軌跡訓練的 MLP（同 v, target, dt） | 現階段最強的行為模仿               |
| `clone`       | 獨立重寫同一條規則                             | **不是偽造品**：行為上限，單獨列出 |

### 7.2 閘二：機制消融（mechanism ablation）

每一階都要說明它量的是哪個機制，並把該機制拔掉重跑：

- `rule`：把規則換成 identity → r3／r4／r5 必須崩。
- `persistence`：刪掉狀態檔 → r6 必須崩。

誤差不動 = 這一階量的是測試的形狀，不是機制。**這道閘就是為了抓「端點式吸引子」那種漏洞**：一個永遠回答 0.3 的常數，在只看終點時誤差 0。

### 7.4 這張表怎麼讀（重點）

1. **r1／r2 不是證據。**
   `copy`（什麼都不做）也通過：閉式解對切分時間不變，常數函數也不變。健全性可以寫，**不能引用**。
2. **r3–r6 目前是可引用的**：控制組失敗、三個偽造品全失敗、拔掉機制就崩。
3. **`clone`
   通過全部**——這是行為測試的天花板。因此「沒有任何同資訊基線能重現這個行為」這種宣稱是**錯的**：一份獨立重寫的同一條規則就能重現。誠實的宣稱只能是機制與 provenance（哪條程式路徑產生這個值），這正是專案六型分數與 provenance 普查在系統層做的事。
4. **r7 仍然缺機制**，`None` 不是通過。

### 7.5 由此得到的研究議程（取代「偽不偽無區別」）

- **更強的偽造品**：帶 dt 的 GRU、neural ODE 當模仿者（現在 `imitate`
  只是 MLP）；模板 + 播音式人設（B 站樣本那一類）要有專門的對照組。
- **機制證據的形式化**：把「哪條路徑產生這個輸出」做成 AL 側的 provenance 標記（`computed`
  / `table` / `template` /
  `learned`），沿用系統層的分類，讓生命層的宣稱也必須報 provenance。
- **每一階的可通過偽造預算要寫下來**：現在是三個偽造品，之後任何新增的偽造品若通過某階，該階自動降級——這條規則已經寫進
  `_row()` 的判定，不需要再討論。
- **消融必須與 rung 同表**：新增階時若沒指定機制，判定只能是
  `unablated`，不能是 admissible。

一句話：**偽與不偽有區別，區別在「誰產生這個值」與「拔掉機制還剩什麼」，不在觀感，也不在能不能找到一個通過的測試。**

## 8. 「同一個模型」與「重複提示詞」的差別（可量測）

使用者指出的分界：**AI+AL 若不在同一個模型裡，就退化為提示詞路線**。這句話要成立，得先分清 AL 狀態到生成之間有哪幾條路，因為它們的外觀相同（狀態變、回覆就變），性質不同。

`./.venv/bin/python scripts/al_channel_audit.py`（實測，非宣稱）：

| 通道             | 路線         | 解析度                   | 模型讀得到 | 模型可忽略 | 可被注入者重現 | 實作位置                                                                                      |
| ---------------- | ------------ | ------------------------ | ---------- | ---------- | -------------- | --------------------------------------------------------------------------------------------- |
| `prompt_text`    | **B 提示詞** | 10,001 值（每值 6 字元） | ✅         | ✅         | ✅             | `prompt_builder.py:_formula_life_intensity_line`                                              |
| `sampling_param` | **C-param**  | 2,001 個溫度（0.2–1.2）  | ❌         | ❌         | ✅             | `router.py:_apply_negotiator_bias` ← `priority_negotiator.heartbeat_voter`／`dli_state_voter` |
| `logit_bias`     | C-logit      | 0（未實作）              | ❌         | ❌         | ✅             | —                                                                                             |
| `model_state`    | **C-state**  | 0（未實作）              | ❌         | ❌         | ✅             | —                                                                                             |
| `routing`        | 路由         | 2 種模式                 | ❌         | ❌         | ✅             | `router.py:4434` → negotiator                                                                 |

### 8.1 差異是性質，不是程度

| 問題                          | B 提示詞                                      | C-param                      | C-state                  |
| ----------------------------- | --------------------------------------------- | ---------------------------- | ------------------------ |
| 模型知不知道狀態？            | 知道（它是句子的一部分）                      | **不知道**（只感覺分布變了） | 不知道，但它**就是**狀態 |
| 狀態能不能被忽略？            | 能（模型可以無視那句話）                      | 不能                         | 不能                     |
| 狀態會不會被 tokenizer 折損？ | 會（本專案的 3dp 文字格點曾是 0/2633 可表示） | 不會（連續參數）             | 不會                     |
| 每回合成本                    | 每值 6 字元 + 模板                            | 0 token                      | 0 token                  |
| 重啟後是否延續                | 只延續「寫進 prompt 的那個數字」              | 只延續最後一次算出的參數     | 延續模型自己的遞歸狀態   |
| 能不能被第三方程式重現        | 能（照抄那句話）                              | 能（直接設溫度）             | 能（若能讀寫權重／狀態） |

結論一：**B 與 C-param 都不是生命證據**，因為兩者都能被一個注入者完整重現；它們回答的是「模型有沒有讀到一句話」，不是「狀態有沒有自己活著」。

結論二：**「同一個模型」在字面上只有 C-state 成立**。C-param 只是介面——它讓狀態繞過 tokenizer，卻沒有進入模型；模型對它一無所知，重啟也不會記得。因此「C-param 比 B 高級」只在一個地方為真：**它不受文字精度與 token 預算限制**（2,001 級 vs
6 字元／值）。

結論三：目前本專案的實作是 **B + C-param +
routing，C-logit 與 C-state 都是 0**。所以對外只能說「AL 影響生成參數與提示詞」，不能說「AL 與 AI 在同一個模型裡」。

### 8.2 仍然要有走 B 路線的 AL 引擎（使用者的要求）

B 路線不是要被淘汰的東西，它有三個不可替代的用途：

1. **可稽核**：狀態以文字出現在 prompt 裡，事後可以逐字重放與審計；C-param 只留下一個溫度數字，C-state 只留下權重。
2. **可接任意後端**：雲端 API 不讓你碰 logits 或內部狀態，B 是唯一可行的耦合；本地 llama.cpp 才有 C-param／C-logit 的空間。
3. **作為對照組**：review
   §9.8 的 A／B／C 三組裡，B 就是「只有提示詞」的 baseline。沒有 B，C 的增益無法量。

因此 AL 引擎應該把路線做成**顯式參數**，而不是埋在程式裡：

```
mode: prompt | param | logit | state      # 缺一就降到下一級
```

- 啟動時依後端能力自動降級（`state > logit > param > prompt`），並把實際使用的路線寫進每次生成的 provenance。
- 報告裡的生命證據只認 `logit` 以上；`prompt` 一律標 `route=prompt`
  且**不計分**。
- 這一條與 §7 的六型分數紀律一致：分數的種類要標清楚，混算就是造假。

### 8.3 工程量（接 §3 的 M4）

| 任務                         | 內容                                                               | 人日  |
| ---------------------------- | ------------------------------------------------------------------ | ----- |
| 路線參數化 + provenance 標記 | `mode` 選擇、降級、記錄                                            | 1.5–2 |
| C-logit                      | 在本地後端上加 logit bias／steering（先確認 llama.cpp 支援與版本） | 3–4   |
| **C-state**                  | 模型自帶持久遞歸狀態 + 重啟測試（唯一讓「同一模型」為真的實作）    | 8–12  |
| A／B／C 統計對照             | 狀態歷史能解釋多少輸出變異                                         | 2     |

**C-state 是這裡真正的分水嶺**：不做它，整個 AI+AL 就只能算「提示詞 + 參數調整」；做了它，「時間作用在狀態上」才第一次作用在**模型**上，而不是作用在一個旁邊的 JSON 檔上。

## 10. 節律源：把否定結果換成機制（2026-11-07）

§9 說「心跳沒有自發節律」。那是對**現有實作**的否定：`dynamic_interval`
是無記憶純函數，不可能振盪。要往前走不是反覆陳述這件事，而是補上缺的那一類東西，再量它是否成立。

### 機制

`core/life/al_oscillator.py`：Van der Pol 型鬆弛振盪器

```
dx/dt = v
dv/dt = μ(1 − x²)·v − ω²·x + drive
```

沒有閉式解，振幅與週期都是從積分裡長出來的；`(x, v)`
連同時間戳落盤，重啟後按實際經過時間繼續積分（`MAX_CATCHUP_S=600`，超過標
`stale`
而不是編一個相位）。生產接法一行：`heartbeat.effective_arousal(arousal, activation, 0.2)`。

### 閘門

`scripts/al_rhythm_source.py`
的判定需要六項全過**且**三個偽造品各至少失敗一項，否則一律
`self-rhythm-not-established`：

| 檢查            | 為什麼它能證偽                                               |
| --------------- | ------------------------------------------------------------ |
| 常數輸入 CV     | 若 CV=0，就是上一個否定結果的形狀                            |
| 週期對 μ 的規律 | 查表節拍在此恆為 0 反應                                      |
| 積分步長不變性  | 若週期隨步長漂移，週期其實是步長的產物                       |
| 相位響應        | 忽略擾動的東西只是 autonomous clock，不是動力系統            |
| 鎖頻舌頭        | 只有強驅動鎖、弱驅動不鎖才算舌頭；全都鎖代表它只是在鏡射輸入 |
| 節拍承接        | 內部週期若沒傳到節拍上，這整個機制與生命無關                 |

結果：**43.54 s 自然週期，常數輸入 CV 0.78，節拍 CV 0.071 且週期 43.54
s（誤差 1e-4）**，判定 `self-rhythm-admissible`。

### 這一步不做什麼

它不把分數往上調。生命證據的定義沒變（控制組失敗 + 全部偽造品失敗 + 拔掉機制就崩），而振盪器只是「自發」這件事的必要條件。下一個可證偽的問題因此變得更具體：**那個相位有沒有改變行為**——同一輸入在不同相位下，決策/回應是否不同，且差異不是亂數造成的。

## 11. 相位 → 決定：節律有沒有用（2026-11-07 續）

§10 結束在一個尚未回答的問題上：43.54
s 的相位有沒有改變行為。有週期不等於有用——鐘也會擺。這一節把問題做成可判定的。

### 接法（兩處，都是狀態層）

1. `al_state.ALSnapshot` 新增 `rhythm` 欄位（`activation` 0..1、`phase`
   0..1），`source["rhythm"] = "core.life.al_oscillator"`。與 `emotion`
   **分開**：`arousal` 是觀測，`rhythm` 是內生，混在一欄就無法逐量歸因（I9）。
2. `al_memory_policy` 的編碼權重多一個來源：

```
weight ← intensity × (1 + 0.4·(arousal − 0.3)) × (1 + 0.2·(activation − 0.5))
```

權重是**寫進記憶**的量，改的是 retrieval 與衰減，不是一句 prompt。所以這條耦合會留下持久痕跡。

### 判準（`scripts/al_phase_effect.py`）

| 檢查       | 結果                                                                          |
| ---------- | ----------------------------------------------------------------------------- |
| 有效應     | 八個相位的權重 0.937 → 1.143，差距 **22.1%**                                  |
| 由相位決定 | 逐樣本（2,400 點）相位解釋權重變異 **96.5%**                                  |
| 控制組不動 | 拔掉 `rhythm` → 權重 **完全相同**（spread 0.0）                               |
| 不是隨機   | 置換 activation 後：變異仍 22.2%，但相位只解釋 **0.66%**                      |
| 偽造品     | 固定 activation（無效應）、wall-clock 正弦（同相位重跑不同 → 不可重現）都被擋 |

判定 `phase-affects-decision`。

### 這證明什麼、還差什麼

證明的是 **state →
decision**：同一個觀測、同一個輸入，只因為系統自己在不同相位，寫進記憶的權重不同，而且差異由相位決定（置換後消失）。這是「內生節律有功能」的第一個證據，比「有節律」強一級。

還差的正是最難那一級：這條路徑**沒有碰 LLM**。生成參數、logits、注意力都沒有被相位影響；`mode: state`
的耦合仍然只到本系統自己的決定。下一步要嘛把相位接進生成參數（C-param，小），要嘛承認 C-state 需要的是一個能被狀態調制的生成路徑（大）。

### 附帶的量測紀律

生產快照從此一直帶 `rhythm`，所以「某一個觀測源對權重的貢獻」這類測試必須把
`rhythm` 釘成
`None`——否則兩個源的乘積混在一起，兩者都不可取證。`tests/core/test_al_memory_policy.py`
與 `tests/core/test_al_arousal.py` 的控制快照都已改成這樣。

## 12. C-param：相位進入生成請求（2026-11-07）

§11 的耦合只到系統自己的決定，沒有碰生成。這一節把相位接到請求參數上——最小、但真實的一步。

### 接法

`core/life/al_generation_params.py`：純函數
`modulate(temperature, max_tokens, snapshot)`

```
T' = clamp(T + 0.15 · 2·(activation − 0.5), 0.1, 1.5)
tokens' = clamp(tokens · (1 + 0.10 · 2·(activation − 0.5)), 64, 8192)
```

生產接點是 `ChatService.generate_text`（`temperature`/`max_tokens`
實際送往 LLM 服務的位置）。`rhythm` 缺席或壞型別 → **原值逐位不動**（D11）。

界線刻意與 router 的 `_apply_negotiator_bias`
相同（0.1–1.5），免得兩處夾出不同範圍。

### 判準（`scripts/al_c_param.py`）

探針不信接線，它把 `ChatService` 的 LLM 服務換成記錄器、實際呼叫
`generate_text`，看最後送出的參數：

| 檢查         | 結果                                                    |
| ------------ | ------------------------------------------------------- |
| 真的到達請求 | 八相位溫度 **0.551 → 0.849**，tokens 461 → 563          |
| 效應可見     | 擺幅 = 42.5% of 0.7                                     |
| 控制組不動   | 無 rhythm → 正好 0.7 / 512                              |
| 由相位決定   | 2,400 樣本相位解釋 **96.5%** 溫度變異；置換後 **0.79%** |
| 偽造品       | wall-clock 正弦：同一相位重跑不同 → 不可重現            |

判定 `generation-params-modulated`。

### 這是什麼級別的耦合

字面上「同一個模型」需要模型的內部狀態被調制（C-state）。這一層是
**C-param**：改的是請求的取樣條件，模型本身不知道自己被調制。它比 §11 強的地方在於**它到了生成**；比 C-state 弱的地方在於**模型可以換掉而耦合消失**。

### 沒有量的東西

沒有量真實模型上的輸出差異。這裡只有參數層證據與一段算術示範（固定 logits
`[2, 0]`，最高機率 token 的機率 0.913（高溫）vs
0.974（低溫））。要量輸出差異必須跑真模型並排除取樣噪聲——那是一個需要 N 次重複與統計檢定的實驗，不是這一步能順手宣稱的。

## 13. C-logit：相位進到模型的機率分布（2026-11-07）

C-param 的問題是「換一個模型耦合就消失」——AL 的狀態從沒碰到模型的輸出。這一節把它接到
**logits**。

### 接法

`core/life/al_logit_bias.py`：純函數
`phase_bias(activation, energy_ids, calm_ids)`

```
offset = 2·(activation − 0.5) ∈ [−1, 1]
energy_ids: += 4.0·offset          # 「高喚醒」詞彙
calm_ids:   −= 4.0·offset          # 「低喚醒」詞彙
```

`apply_to(scores, bias)`
回傳套用後的分數（不就地改輸入）。因為 softmax 對 logits 單調，這**直接改變模型對下一個 token 的機率**，不是改變請求參數。

### 判準（`scripts/al_c_logit.py`，**真模型** `qwen2.5-1.5b-instruct-q4_k_m`）

用 llama.cpp 的 `logits_processor`
攔下最後一個位置的 151,936 維 logits，套用偏移後量分布：

| 相位 activation | p(energy)  | p(calm)    | Δ      | KL        |
| --------------- | ---------- | ---------- | ------ | --------- |
| 0.005（谷底）   | 0.0000     | **0.3347** | −0.335 | **0.930** |
| 0.213           | 0.0002     | 0.0866     | −0.086 | 0.119     |
| 0.669           | 0.0077     | 0.0024     | +0.005 | 0.008     |
| 0.997（峰）     | **0.0970** | 0.0002     | +0.097 | 0.295     |

| 檢查               | 結果                                          |
| ------------------ | --------------------------------------------- |
| 分布真的動了       | 最大 KL **0.930**                             |
| 跨越中點           | Δ 由 −0.335 翻到 +0.097                       |
| 隨 activation 單調 | r = **0.918**                                 |
| 中點控制組         | 偏移全 0 → logits **逐位相同**                |
| 置換對照           | 變異仍在，r 掉到 **−0.337**                   |
| 偽造品             | wall-clock 正弦 → 同一相位重跑不同 → 不可重現 |

判定 `phase-reaches-logits`。

### 閘門自己抓到的兩個 bug（值得記）

第一版回報 KL 恰好 0，看起來像「偏移無效／耦合不存在」。實際是量測工具錯兩次：

1. 記錄的是**偏移前**的 logits（拿中間量當結果）；
2. 就地修改複本、回傳原陣列（llama.cpp 只看回傳值）。

修好之後同一份機制立刻顯示 KL 0.93。教訓與 r6/`al_power_cycle`
相同：**量測工具本身要有反例測試**，否則它會穩定地報「沒有」。

### 邊界

- 這是**外部施加的 logit 偏移**（logit_bias / debiased
  decoding 那一類），不是模型內部狀態被調制。
- 生產供應商是 HTTP 客戶端（`llamacpp.py` →
  `/v1/chat/completions`），客戶端不知道伺服器的 token id 表，硬塞 `logit_bias`
  會變成猜 id。要進生產需要一個 in-process 的解碼器；這裡提供的是那條路的介面（`phase_bias` +
  `apply_to`）與它的證據。
- 沒有量「取樣出來的句子變了什麼」。分布 → 句子需要多次取樣與檢定。

## 14. C-state：相位改的是模型的內部體質（2026-11-07）

C-logit 推的是模型的輸出分布，模型內部仍然不知道。這一節改的是 GARDEN
SNN 的**發火閾值**：同樣的 `input_keys`、同樣的 `W`、同樣的
`timesteps`，只因為內部興奮度不同，脈衝樣式就不同。

### 接法

`core/life/al_snn_modulation.py`（純函數）+ `ai/garden/snn_core.py::forward`：

```
thr_mult = hormonal_modulator × (1 − 0.5·2·(activation − 0.5))
threshold = max(0.01, base_threshold · thr_mult)
```

相位高 → 閾值低（0.5×）→ 同一個線索更容易擴散；相位低 → 閾值高（1.5×）→ 什麼都不擴散。`al_modulation`
缺席或壞值 → 倍率 1.0，行為與接線前逐位相同。

### 判準（`scripts/al_c_state.py`）

| 檢查               | 結果                                                                |
| ------------------ | ------------------------------------------------------------------- |
| 內部效應           | 谷相位輸出 **0 個概念**（基線 4 個），L1 = **1.0**                  |
| 結構改變           | 4 個概念**全部消失**，不是數值漂移                                  |
| 隨 activation 單調 | Spearman ρ = **0.952**（置換 0.381）                                |
| 輸入未變           | 兩次呼叫的 `input_keys` 逐位相同                                    |
| 控制組             | 完全不加調制 → 輸出**逐位相同**                                     |
| 切換點隨動力學移動 | 權重 0.5 / 0.6 / 0.75 → 交叉於 activation **0.525 / 0.330 / 0.038** |

判定 `phase-changes-internal-dynamics`。

最後一列是這一節的重點：如果調制只是寫死的
`if activation > 0.5`，切換點不會隨權重移動。它移動了近 0.5，說明切換點是**動力學算出來的**。

### 誠實描述

- 這是**全或無**的效應（0 或 4 個概念），不是漸變。這是 SNN 的本性：脈衝本來就是全或無。說「相位調節強度」會是錯的；正確說法是「相位決定這條概念鏈會不會擴散」。
- 這是
  **C-state 在我們自己的模型上**（GARDEN，權重是本專案的）。它不主張 Qwen 那個黑箱模型的內部狀態被調制——那一層仍需要能餵 hidden
  state / KV 的解碼器。
- 沒有量語意品質，也沒有量「AL 讓模型學到什麼」（那是權重層）。

## 15. C-learn：相位決定「這次經歷被記得多深」（2026-11-07）

前四級改的都是**這一刻**：請求參數、輸出分布、發火閾值。它們不改變模型明天是什麼樣子。這一節改的是權重會被推向哪裡——同一個模型、同一批資料、同一個順序、同一個
`lr`，只因為經歷它們時的內生相位不同，留下來的結構就不同。

### 接法

`core/life/al_learning_gate.py`（`learning_gain()`：activation
→ 可塑性增益 0.4–1.6）接到 `TensorSNNCore.hebbian_update(plasticity=…)`，實際
`lr` 乘上增益。缺席／`None`／布林／`NaN`／負值 →
1.0（逐位不變）。語義：相位高（喚醒高）→ 此刻的共現較容易固化；相位低 → 同樣的共現幾乎不留痕。

### 判準（`scripts/al_c_learn.py`）

72 個互不相同的配對，每對只經歷一次，`lr` 0.5、`target_strength` 0.9、無 decay：

| 檢查           | 結果                                                                   |
| -------------- | ---------------------------------------------------------------------- |
| 權重取決於相位 | 受訓配對平均權重 **0.181 → 0.719**（擺幅 0.537）                       |
| 結構改變       | 跨過 0.3 的配對 **0 → 72**（全部或全不）                               |
| 排序隨相位     | ρ(平均權重, 增益) = **1.000**；ρ(已固化數, 增益) = **0.905**           |
| 控制組逐位相同 | `plasticity` 1.0 / `NaN` / 0 / −1 / `None` → 與不傳**逐位相同**（0.0） |
| 可重現性       | 真實振盪器排程兩次重跑逐位相同；wall-clock 正弦兩次不同                |

判定 `phase-decides-what-gets-kept`。

### 誠實描述

- 每對只經歷**一次**。跑多輪會把權重推到
  `target_strength`，增益差異就被飽和抹掉——第一版跑 3 輪量到 ΔW≈0，那是**參數選擇**，不是機制不存在。這也是這條路線的一般教訓：量到「沒差」時先確認機制有沒有被天花板壓住。
- 只主張「相位改變了留下來的結構，方向由增益決定」。**沒有**主張「這樣學比較好」——沒有量下游任務表現。
- **尚未接生產**：`GARDENEngine.learn_from_interaction` / `learn_batch` 目前不傳
  `plasticity`，所以這條路徑還沒被線上聊天驅動。接上去是下一步（介面已備、預設中性）。

## 16. C-learn 接上生產路徑（2026-11-07 續）

§15 證明的是 `hebbian_update(plasticity=…)`
有效——那是模型層。這一節問的是另一件事：**線上聊天走的那條路**有沒有讀到相位。如果沒有，C-learn 就只是實驗室裡的東西。

### 接法

`GARDENEngine._plasticity_gain()`：

```
get_rhythm_tracker().activation_preview() → learning_gain() → 增益
```

- `learn_from_interaction`：每次互動讀一次，傳進
  `hebbian_update(plasticity=…)`，並在回傳摘要多一個 `plasticity`
  欄位（可觀測，不必猜）。
- `_batch_train_associations` →
  `_batch_hebbian_update`：批次開頭讀一次，結構更新與 auto-regressive 更新都用同一個增益。
- **`activation_preview()`（新）**：只讀 `(x, v)` 現值，不推進、不落盤。原本的
  `activation()` 每次呼叫都會
  `_save()`，批次學習每個樣本都用它等於每個樣本寫一次磁碟。

### 判準（`scripts/al_c_learn_wired.py`）

同一個引擎、同一批 8 段互動、同一個順序，只換 `get_rhythm_tracker()`
背後的相位：

| 檢查             | 結果                                                                         |
| ---------------- | ---------------------------------------------------------------------------- |
| 生產路徑讀到相位 | 谷 vs 峰的 SNN 權重最大逐點差 **0.1671**                                     |
| 增量隨相位縮放   | 每段互動 `hebbian_delta` **0.2365 → 0.8724**，比值 **3.688**（增益比 3.717） |
| 批次路徑也接了   | `learn_batch` 谷 vs 峰 **0.0275**                                            |
| 控制組逐位相同   | 節律源**拋錯**或回 **NaN** → 與中立相位 **0.0**                              |
| 不是噪音         | 同一相位跑兩次 **0.0**                                                       |

判定 `phase-reaches-learning-in-production`。

### 為什麼控制組換了

第一版控制組是「完全沒有 tracker」，它失敗了（ΔW 0.052）——因為
`get_rhythm_tracker()`
是單例，**一定會建一個 tracker**，所以「沒有源」在生產環境不是一種真實狀態。改成「源壞掉」更強也更貼近現實：拋錯與 NaN 都必須收斂到中性，學習既不能停擺也不能變成亂數。

### 誠實描述

- **有接線 ≠ 有效果**。這裡量的是「相位會改變學習留下的權重」，**沒有**量「這樣學比較好」：沒有 held-out 任務、沒有下游品質指標。長期線上效果需要長時間跑 + 評估，仍未做。
- 增益一路從 `learning_gain()` 進來，範圍 0.4–1.6；真正的振幅上限受
  `target_strength` 與飽和支配（§15 的教訓）。
- 黑箱模型的 hidden-state 調制仍 **✗**：需要能吃 hidden state / KV 的解碼器。
