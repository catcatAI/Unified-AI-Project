# 分層規劃填空生成（Hierarchical Plan-then-Fill）

> **狀態：探索中，尚無任何實測證據。**
> 本文是設計記錄與驗證計畫，不是功能宣稱；在第 6 節的探針有可重跑的數字之前，不進
> `docs/STATUS_MATRIX.md`。建立日期：2026-11-11。外部文獻的對應來自記憶，引用前需逐篇核對。

## 1. 名稱

| 範圍     | 名稱                                                 | 一句話                                                  |
| -------- | ---------------------------------------------------- | ------------------------------------------------------- |
| 整體     | 分層規劃填空生成（Hierarchical Plan-then-Fill，HPF） | 先預測結構（格式、段落、token 位置），再填內容          |
| 快取     | 殘餘計畫快取（Residual Plan Cache，RPC）             | 上一步預測了但尚未輸出的位置／token，存起來給下一步融合 |
| 完成判斷 | 剩餘清空判據（Remainder-Empty criterion）            | 快取清空且沒有新預測出的位置，才算完成                  |

血緣（據我所知）：非自回歸生成與長度預測（NAT、Mask-Predict）、分層規劃（先大綱後展開）、predictive
coding（保留預測再用新輸入修正）、speculative decoding 對未被接受草稿的重用。

## 2. 想法

```
輸入 tokens
  → 預測 格式 → 段落 → token 位置（數量與佈局）→ token 內容
  → 與「上次剩餘」融合
  → 輸出一部分
  → 未輸出的預測存入快取（RPC），留給下一步
```

「」代表 **token 位置**，不是內容。示意：

```
輸入：「你好」「。」
預測位置：「」「」「」「」……
填空輸出：「你好」……
```

## 3. 為什麼值得試

- 每一層都能從原始文本用規則自動抽出（格式、段落、長度、token），不需人工標註，每層可單獨量測條件熵。
- 快取存的是「預測」，不是文字或隱向量：可檢視、可修剪、可隨時間衰減。這是「時間作用於狀態」且「不經 context」的候選機制。
- 剩餘清空是顯式的進度／完成訊號，比 EOS 的隱式機率判斷更可檢視。
- **理論上限**：骨架只是潛變數，p(x) = Σ
  p(s)p(x|s)，總資訊量不變。好處只可能來自易學性、可控性與泛化，不會來自「更準」。任何比較都必須把骨架位元計入總成本。

## 5. 風險與開放問題

1. **融合規則就是整個設計**：舊預測與新預測衝突時誰贏？舊的壓過新輸入會固執，全忽略則快取無用。候選：信心 × 新鮮度加權。
2. **串接誤差（exposure
   bias）**：訓練用真實上層結構、測試用預測的，會錯位。需用模型自己的上層輸出訓練或加噪。
3. **長度錯了補不回來**：緩解是取樣多個長度、各自填完、用模型分數重排。
4. **獨立填空的重複與不一致**：需迭代（先填高信心位置、其餘重遮），且前向必須消耗上一輪結果（見第 4 節第 5 列）。
5. **完成的是「計畫」不是「任務」**：計畫低估或漏項時會誤判完成。需要獨立驗證（確定性引擎、規則檢查），不能只靠快取。
6. **本質上是遞迴狀態**：公平的對照組要含 carry-over 狀態模型（RNN、Transformer-XL）與連續時間模型（LTC、CfC），不只是 Time2Vec 加 LSTM，否則會被質疑是稻草人。
7. **短回覆看不出差異**：價值預期出現在多輪、長輸出、結構性輸出。
