## 1. 名稱

| 範圍     | 名稱                                                 | 一句話                                                  |
| -------- | ---------------------------------------------------- | ------------------------------------------------------- |
| 整體     | 分層規劃填空生成（Hierarchical Plan-then-Fill，HPF） | 先預測結構（格式、段落、token 位置），再填內容          |
| 快取     | 殘餘計畫快取（Residual Plan Cache，RPC）             | 上一步預測了但尚未輸出的位置／token，存起來給下一步融合 |
| 完成判斷 | 剩餘清空判據（Remainder-Empty criterion）            | 快取清空且沒有新預測出的位置，才算完成                  |

血緣（據我所知）：非自回歸生成與長度預測（NAT、Mask-Predict）、分層規劃（先大綱後展開）、predictive
coding（保留預測再用新輸入修正）、speculative decoding 對未被接受草稿的重用。

## 2. 想法

```
輸入 tokens
  → 預測 格式 → 段落 → token 位置（數量與佈局）→ token 內容
  → 與「上次剩餘」融合
  → 輸出一部分
  → 未輸出的預測存入快取（RPC），留給下一步
```

「」代表 **token 位置**，不是內容。示意：

```
輸入：「你好」「。」
預測位置：「」「」「」「」……
填空輸出：「你好」……
```

## 3. 為什麼值得試

- 每一層都能從原始文本用規則自動抽出（格式、段落、長度、token），不需人工標註，每層可單獨量測條件熵。
- 快取存的是「預測」，不是文字或隱向量：可檢視、可修剪、可隨時間衰減。這是「時間作用於狀態」且「不經 context」的候選機制。
- 剩餘清空是顯式的進度／完成訊號，比 EOS 的隱式機率判斷更可檢視。
- **理論上限**：骨架只是潛變數，p(x) = Σ
  p(s)p(x|s)，總資訊量不變。好處只可能來自易學性、可控性與泛化，不會來自「更準」。任何比較都必須把骨架位元計入總成本。

## 5. 風險與開放問題

1. **融合規則就是整個設計**：舊預測與新預測衝突時誰贏？舊的壓過新輸入會固執，全忽略則快取無用。候選：信心 × 新鮮度加權。
2. **串接誤差（exposure
   bias）**：訓練用真實上層結構、測試用預測的，會錯位。需用模型自己的上層輸出訓練或加噪。
3. **長度錯了補不回來**：緩解是取樣多個長度、各自填完、用模型分數重排。
4. **獨立填空的重複與不一致**：需迭代（先填高信心位置、其餘重遮），且前向必須消耗上一輪結果（見第 4 節第 5 列）。
5. **完成的是「計畫」不是「任務」**：計畫低估或漏項時會誤判完成。需要獨立驗證（確定性引擎、規則檢查），不能只靠快取。
6. **本質上是遞迴狀態**：公平的對照組要含 carry-over 狀態模型（RNN、Transformer-XL）與連續時間模型（LTC、CfC），不只是 Time2Vec 加 LSTM，否則會被質疑是稻草人。
7. **短回覆看不出差異**：價值預期出現在多輪、長輸出、結構性輸出。

### 6.1 預註冊：狀態通道（P5）＝ AL 核心問題（2026-11-11 寫死）

P5 不是選配。其他四個探針量的是「這個生成方式好不好」，只有 P5 能讓「AL 的狀態是不是一條真通道」變成是非題。以下內容在跑之前固定；跑完不得回頭改門檻、改切分、改指標，也不得用測試集調任何東西（含早停）。

**宣稱**：內容模型固定、輸入分布固定的前提下，AL 狀態（`get_al_state()`
的快照）對輸出**結構**（長度與骨架）的預測力，高於同一模型看不到狀態時的水準，**且**
高於看到被打亂的狀態。

**四組（同一個內容模型、同一份權重，只改通道）**

| 組  | 通道                                                        | 用途                                   |
| --- | ----------------------------------------------------------- | -------------------------------------- |
| A0  | 無狀態（對照）                                              | 基準線                                 |
| A1  | 狀態 → 結構先驗（只影響長度／骨架分布，不進輸入）           | 待驗宣稱                               |
| A2  | 狀態**打亂**（同一份狀態池，跨回合隨機配對）                | 決定性否證：A2 ≈ A1 表示狀態沒攜帶資訊 |
| B   | 狀態當**普通輸入**（拼進輸入序列；Time2Vec+LSTM，另跑 CfC） | 排除「只是多給了一個特徵」             |

A2 是整份設計的關鍵。A1 贏 A0 可能只因為多了一個條件變數；只有
**A1 贏 A2**，「狀態帶了關於這一回合的資訊」才成立。

**狀態向量**：`core.life.al_state.ALSnapshot`
的九個可觀測欄位（`life_phase`／`life_cycle_state`／`health`／`intensity`／`emotion`／`tendency`／
`rhythm`／`ticks`／`born_at`）。`drift` 是 derived、不落盤也不進模型。缺值保持
`None`（D11）**不得補 0**：補 0 會把「沒觀測」變成「觀測到 0」，A1 會贏在假訊號上。

**輸出結構**（不讀文字內容也能算）

- 長度：token／字元數分桶（1、2–4、5–8、9–16、17+）
- 骨架：格式（是否條列／程式碼圍籬）、段落數、句數
- 兩者都取雜湊簽章；事件檔只存簽章與桶號，不存原文

**資料**：時間切分（先前 → 訓練、之後 → 測試），切點寫進凍結清單；匯出 JSONL 後算 SHA-256 一併寫進清單，測試集只讀一次。

**主要指標（只有一個）**：`H(結構) − H(結構 | 狀態)`，在**同一內容分層內**計算（輸入長度桶 × 主題桶），避免「深夜使用者講的話本來就短」被記成狀態的效果。配對 bootstrap（1,000 次）給 95% 區間。

**次要指標**：A1 vs B（是否只是多特徵）；A1 對狀態單調變化的敏感度。

**最小效果（跑之前寫死，三條全過才算成立）**

1. 主要指標 95% 區間**下界 > 0**
2. A1 相對 A2 的降幅 ≥ **10%**（同一分層、同一樣本）
3. 至少 **4/5** 個隨機種子同號（種子清單先寫死）

**停止條件（不可事後放寬）**

- A1 ≈
  A2（差距區間跨 0）→ 狀態不帶資訊：撤回「AL 是生成通道」的強宣稱，保留工程基礎（單一時鐘、快照、事件寫入口），分支封存，負面結果寫進 CHANGELOG。
- A1 ≈ B → 贏的只是「多一個特徵」：同樣撤回，並把結論補進第 5 節第 6 條。
- 分層後每格 < 200 回合，或狀態覆蓋率不足（某欄位 100% 為 `None`）→
  **不跑**，標「樣本不足」，不得用不足的樣本給方向性結論。

**這輪不做**：不改 `core_model.py`、不動主推論路徑、不進
`docs/STATUS_MATRIX.md`、不把結果寫成 L0–L3 或核心分。這份量的是「訊號有沒有效」，不是「智能幾分」。

## 8. 應用切片（建議，2026-11-11）

### 8.1 為什麼是先做應用

三件事同時成立，所以應用不是「換題目」，而是這一輪唯一能往前推的動作：

1. **實驗缺資料，而資料只能從應用長出來**（6.2：目前 0 組真實配對）。再多跑一次合成或小樣本實驗，只會多一個無法裁決的數字。
2. **可用的能力已經在表層量到了**（系統分 6.41／10：事實 5.3、數理 8.0、改述 7.5、對話記憶 8.8）。這些能力現在只被探針用到，沒有使用者。
3. **應用會逼出真正的缺陷**：延遲、斷線、記憶保留、回答錯時的補救 —— 這些是探針照不到的，而它們正好決定「狀態 → 輸出」在真實互動裡有沒有訊號。

前提不變：應用跑在**已量到的表層能力**上，不得宣稱核心智能（核心分仍是 0.00／10）。

1. **來源可見**：回覆要標示生產者 —— 現有 `_format_chat_response()` 已輸出

   → `蓝色。`）。要修的是觸發條件，不是新管線。宣告層的回歸線是
   `scripts/audit_placement.py`
   現在 7/7 一致；它量的是宣告 vs 生產者，**不是**棄權率，兩者分開看。
3. **教了就記得，且更正生效**：使用者教一句事實 → 下一回合可召回；說「不是 A，是 B」→ 下一句就用 B。既有契約：`tests/ai/test_taught_facts.py`（16 條）。
4. **算術不經模板**：`2加3等於多少`
   這類由確定性引擎回答（`deterministic-math`），回覆不得包成「答案是 …」的模板句。
5. **不得自我石化**：模板與記憶回覆不得被當成新語料回教；`response_template`
   原句重播那條待決（見 6.3）先不改，但要在 UI 標成 `memory`。
6. **可跑**：後端離線時前端進本機模式而不是壞掉（`unified-shell`
   的 Offline 狀態已經是這個行為，需保持）。

### 8.4 P5 需要的最小觀察（同意制）

應用產生的事件只寫**結構**，不寫原文；預設關閉（`ANGELA_TURN_OBSERVATION=1`
才開），使用者開啟才記。實作：`apps/backend/src/ai/lifecycle/turn_observation.py`，寫入
`<data root>/observations/turns-YYYY-MM-DD.jsonl`（可用
`ANGELA_TURN_OBSERVATION_DIR` 改路徑）。

```
{turn_id, session_hash, day, state:{八欄, 缺值 null}, user_move, source,
 out_len, out_len_bucket, skeleton:{lines,paragraphs,sentences,bullets,
 numbered,code_fence,question}, skeleton_sig, consent}
```

- 不記原文 → 就算外洩也還原不出對話；P5 的主要指標（長度／骨架）不需要文字。
- `user_move`
  是**這一回合使用者訊息**的標籤（question／request／repair／statement／empty），在分析時讀成「上一個回答的下一步」：因此 continue／repair／end 可以在讀取端算出來，日誌永遠 append-only、不必回頭改寫。
- `state` 是 `get_al_state()` 的八個可觀測欄位；缺值保持
  `null`，補 0 會製造假訊號。
- 樣本量由 6.1 的分層要求反推：每格 ≥ 200 回合、約 10 格 →
  **約 2,000 回合**；在那之前跑 P5 只會得到「樣本不足」。
