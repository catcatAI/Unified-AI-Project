## 0. 一句話

**AL 底層只有四件事：時鐘、狀態、轉移、錨。**
其他全是欄位。狀態是一份快照，轉移是純函式，錨是唯一值，時鐘只有一個 —— 四者缺一，「漂移」與「連續性」就沒有定義，AL 也就退化成另一個會聊天的 prompt 層。

## 1. 職責與非職責

### 1.1 AL 負責

| 職責         | 說明                                                          |
| ------------ | ------------------------------------------------------------- |
| 狀態演化     | 給定當前狀態、事件與 `dt`，算出下一個狀態                     |
| 時態         | 半衰期、衰減、固化、順序、不可逆、跨重啟連續性                |
| 身份連續性   | 核心錨的維護、漂移度量、修正參數                              |
| 影響權重     | 誰的話聽多少（`ai` / `user` / `group` 三作用域）與聽多久（τ） |
| 記憶策略     | 輸出 retention/decay policy，**不輸出內容**                   |
| **本能驅動** | **直接驅動身體/表現層的反射與協調，不經過 AI 引擎（§11）**    |

### 1.2 AL 明確不做（寫進門禁，不是靠紀律）

1. **不做當下推理** —— 轉移函數裡沒有 LLM、沒有 prompt、沒有工具呼叫。
2. **不存知識與內容** —— 標 `derived` 的欄位一律不落盤，每次從記憶層現算。
3. **不寫 prompt、不組上下文**
   —— 那是 AI 層（`prompt_builder`）的事，它只能**讀**快照。
4. **不直接存取記憶層的紀錄** —— 只輸出策略，由記憶層執行。
5. **不做表現層** —— Live2D、字幕、語音是表現層，不是第四核心。
6. **不決定說什麼** —— 身體怎麼動歸 AL（§11），說什麼歸 AI；兩者交換的是
   **模式與目標**（AI→AL）和**身體狀態事件**（AL→AI），不是逐幀命令。

> 對應三分法的三條邊界：AI 不擁有長期身份（→
> §9 只讀快照）、AL 不直接存知識（→ 本節 2）、記憶不決定我是誰（→
> §6 錨由 AL 單點決定）。
> **這三條在今日代碼中全部被違反**，因此它們是**門禁目標**，每條在 §13 有機器可驗的對應項。

## 3. 狀態：`ALState` 快照

### 3.1 欄位類別（核心設計）

每個欄位必須標四類之一。**類別決定時常數的上界、是否落盤、參與哪些運算**：

| 類別        | 含義                           | 落盤            | 時常數 | 參與漂移                            |
| ----------- | ------------------------------ | --------------- | ------ | ----------------------------------- |
| `invariant` | 錨：幾乎不動                   | ✅              | ∞      | ✅（對核心錨的偏離 = 最嚴重的漂移） |
| `slow`      | 傾向：人格、傾向強度、影響佔比 | ✅              | 時～天 | ✅                                  |
| `fast`      | 狀態：情緒、能量、健康         | ✅              | 秒～分 | ❌（本來就該變，**不修正**）        |
| `derived`   | 投影：從記憶現算               | ❌ **禁止落盤** | —      | —                                   |

**`derived` 不落盤是把「AL 不直接存知識」做成機械規則的手段**：存了就是違規，§13
I3 直接查。這也讓「記憶堆多了身份被內容淹沒」在結構上不可能發生 ——
AL 永遠只持有摘要與傾向。

### 3.2 v1 最小欄位集（8 個，每加一個要配一個 τ 與一個測試）

| 欄位                | 類別                      | 說明                                                                                                                              |
| ------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `born_at` / `ticks` | `invariant`               | 單一時間基準（§4）                                                                                                                |
| `life_phase`        | `invariant`（受控遷移）   | 沿用 `LifePhase` 五態                                                                                                             |
| `health`            | `fast`                    | 來源 `MetabolicHeartbeat`                                                                                                         |
| `intensity`         | `slow`                    | 來源 `LifeIntensityFormula`（3 實例歸一）                                                                                         |
| `emotion`           | `fast`                    | PAD 三分量；補上今日缺失的持久化                                                                                                  |
| `tendency`          | `slow`                    | 人格 μ/σ，來源 `LifeEssence`（1.7MB 檔收斂）                                                                                      |
| `drift`             | `derived`（值）/ 計算屬性 | `ζ` 連續性 + `η` 結構漂移 + `identity`（離錨**且仍在動**，2026-10-28），三鍵皆未觀測則整欄 `None`；`find_drift()` 仍無生產呼叫 |
| `maturity`          | ❌ 不進 schema            | 2026-10-25 裁決：後端 L0–L11 為死碼已刪（孤兒證據表），前端另有一套 `maturity-tracker.js` 與任何後端指標無關——AL 不擁有成熟度階梯 |

> 為什麼 `drift` 是 `derived`
> 而不是被寫入的值：漂移是**相對於錨的計算結果**，寫入會造成「指標與錨不同步」——今日 η 恆 0 卻被 5 處讀取，就是這個病的成品。

## 4. 時鐘

1. **單一時間基準**：`born_at`（首次初始化時持久化）與
   `ticks`（每次推進持久化）。所有衰減只吃**同一個
   `dt`**（由 tick 推進計算），**wall-clock 不得直接參與衰減**。
2. **多迴圈可保留**，但它們只是**取樣頻率**，不是時間基準：DLI 的 1s/10s/60s、heartbeat 的 2–10s、聊天的每回合 —— 各自取樣後把
   `dt` 交給同一個轉移函數。
3. **三種時間尺度正名**：`tick`（秒級取樣）、`turn`（對話回合）、`epoch`（跨重啟／跨版本／大修正）。
4. **跨重啟連續**：進程啟動時先讀持久化的
   `born_at`/`ticks`，**不得以當前時間重建**。

## 5. 轉移：純函式

```python
S(t+1) = F(S(t), events, dt)   # 純函式、無 I/O、無 LLM、可重放
```

**唯一算子**（泛化自 `core/bio/hormone_kinetics.py` 的 `metabolize()` /
`calculate_metabolism_rate()`，該數學今日只服務激素）：

```
v ← target + (v − target) · e^(−dt/τ)
```

- 每欄位一個 τ（由欄位類別決定上界，見 §3.1）；
- 事件只改變 `target`，不直接改變 `v`；
- 純函式是可測性的來源：不啟動伺服器、不呼叫模型即可測衰減、單調性、可重放性。

**結構保證**：AL 裡沒有可以放推理的地方 —— 不是靠「記得不要放」，是靠函數簽名。

## 6. 錨：漂移的定義

**漂移 = 距離錨。沒有錨，`drift`
這個詞無意義**（今日 η 恆 0、ζ 從未被寫，根因即此）。

### 6.1 錨不可混合（重要）

**身份錨是「唯一」的量，禁止多源加權平均。**
兩個身份平均出的是一個統計中間值，它沒有主張，且會讓「漂移」的參照變成一團雲。錨的多層解析用**優先鏈**（先命中先算）：

```
user 宣告 → group → ai 基準 → config 預設
```

與專案既有慣例一致（`magic_numbers` 的 profile-specific > profile global >
global feature > default 即優先鏈）。**可加權的是參數（§7），不是錨。**

### 6.2 三層錨

| 錨     | 內容                         | 更新                                   |
| ------ | ---------------------------- | -------------------------------------- |
| 核心錨 | 身份名、使用者宣告的核心價值 | 幾乎不動（`invariant`）                |
| 慣性錨 | 人格傾向 rolling baseline    | 慢 EMA，天級（對應 `LifeEssence` μ/σ） |
| 狀態錨 | 本輪基線，抓突變             | 分鐘級                                 |

**錨這個概念在專案裡已存在兩次**（`output_anchor.py` 的 `anchored_decode`、
`AnchorLearningEngine`/`anchor_learning.py`），AL 是把它第一次用在身份上 —— 屬收斂，非新造。

### 6.3 量測

直接用現成的
`core/state/temporal.py`：`find_drift(axis, field, expected, threshold)`、
`trend()`、`anomalies()`（318 行、零依賴，**目前只有測試呼叫**）。 `ζ` / `η`
**沿用既有名詞**，不另起新詞 ——
prompt 已在讀它們，把假值換成真值比發明新詞便宜。

#### 6.4 身份錨的落地記錄（2026-10-28）

`core/life/identity_drift.py`（純函式，無 I/O、可重放）：

* **錨 = `LifeEssence.mu_history()` 的第 0 代祖先核心** —— 觀測得到、
  `data/life_essence_state.json` 持久（146 代 + 當前），跨重啟不歸零；
  **不是預設值**（沒有觀測背後的錨不算錨，D11）。使用者宣告的核心價值仍無
  介面 → Q1 未決，所以这里叫「origin」不叫「核心錨」。
* **時間係數**：慢/快兩層 τ 走配置（`behavior.default.yaml` 的
  `identity_tau_slow=20` / `identity_tau_fast=5.0`，單位＝世代 epoch，§4.3），
  讀路徑用 `lifecycle_value` 而**非** `timing_value` —— 後者乘硬體倍率，同一份
  配置會在不同機器量出不同的人格時間常數（測量隨硬體變 = 量測缺陷）。讀路徑有
  測試釘住，防再變成 §7.2 說的死鍵。
* **量測不用相關係數**：r 對位移不變（狀態停在離錨 0.4 的常數位置 r 仍是 1），
  錨是常數時倉內 `TemporalState.correlation` 回 `0.0`（偽裝的假值）—— 拿 r
  反證漂移會得到「沒有漂移」的錯覺。改用 `distance / SE`（`n_eff = (Σw)²/Σw²`
  修正指數加權的假樣本數），並要求「離開錨**且仍在動**」才確認。
* **產出與消費者**：`drift["identity"] ∈ [0,1]`（0＝量到沒在漂，未觀測→不進
  dict）→ `retention_policy` 取最大（留短）與 `consolidate` 固化閘（>0 不固化，
  只延後保護不改寫狀態）。實測本機 `_al_drift()`：
  `{'eta': 0.0, 'identity': 0.5613}`（SOCIAL_ORIENTATION 離第 0 代 −0.56 且仍在動；
  DEPTH_DRIVE −0.47 但已平息 → 0.0）。
* **穩定 ≠ 智能**：核心分 0.00/10、生產路徑 0 句回覆由模型產生
  （`MEASUREMENT_MAP` 2026-10-24）。錨與閘穩定的是傾向，替系統長不出能力。

## 7. 雙控參數層（AI / 使用者 / 群體）

### 7.1 兩條路，不可混用

| 量                                     | 合成方式              | 說明 |
| -------------------------------------- | --------------------- | ---- |
| **錨**（身份、核心價值）               | **優先鏈**，不混合    | §6.1 |
| **參數/係數**（τ、修正力度、影響佔比） | **加權混合 + 各自 τ** | 本節 |

### 7.2 一階濾波器組（佔比綁 τ）

固定佔比在嘈雜工況下不成立：「一時的梗」與「長期的風向」不該有相同權重。所以**每個源有各自的目標值
`v_s` 與各自的時間常數 `τ_s`**，佔比決定平衡點，τ 決定逼近速度：

```
x_s ← v_s + (x_s − v_s) · e^(−dt/τ_s)      # 每個源先各自濾波
effective = Σ_s w_s · x_s                    # 再按佔比合成
```

| 源                         | 建議 τ | 意義                 |
| -------------------------- | ------ | -------------------- |
| `ai`（AI 自身基準）        | ∞      | 自我不會「一時」改變 |
| `user`（個人）             | 小時級 | 個人的持續傾向       |
| `group_fast`（當下在場者） | 分鐘級 | 當下的梗，自然衰減   |
| `group_slow`（歷史累積）   | 天級   | 風向，沉澱           |

`τ_s` 與 `w_s` 都是**配置鍵**（走 `magic_numbers`
慣例），改一個鍵全跟著走 —— 即「一個配置值改多跟著走」。

### 7.3 四條硬規則（安全帶，v1 必須進 schema 驗證，違反則 boot 失敗）

1. **歸一**：`Σ w_s = 1 ± ε`，否則有效值跑出合法區間。
2. **自我地板**：`w_self ≥ MIN`（配置項，紀律上不隨便調）。佔比會隨時間演化（它也是
   `slow` 欄位），沒有地板就會滑向「越聽群越不是自己」——
   **正是三分法要防的那種漂移**。
3. **歸因**：快照同時記 `effective`、各分量、各 `weight`、`source`、快照
   `version`。否則日後「怎麼突然變了」無法取證。
4. **唯一寫入口**：對參數的寫只能經 §9 的事件通道，不存在第二條改值路徑。

### 7.4 作用域實作範圍（2026-10-25 決定）

**目標工況「AI 直播」定為未來工況**（原因：Live2D 與前端尚待驗證），因此 schema
**第一版就留槽位、但只實作兩個作用域**：

| 作用域  | v1                            | 說明                                                   |
| ------- | ----------------------------- | ------------------------------------------------------ |
| `ai`    | ✅ 實作                       | AI 自身基準                                            |
| `user`  | ✅ 實作                       | per-user，沿用 `data/identities.json` 的 per-user 慣例 |
| `group` | ⬜ **留槽位、填預設、不啟用** | 啟用時 §7.5 的三項為**前置必備**，不可省               |

### 7.5 `group` 啟用前的三項必備（為未來工況預留，不在 v1 實作）

1. **穩健聚合 + 每源封頂**：群體內**每人貢獻要有上限**。`w_group`
   管「群佔多少」，封頂管「群內每人佔多少」——缺一則一個人刷 1000 條等於他一個人說了算。均值在直播工況下會被高聲量觀眾拉偏（常態，不是例外），需用中位數/截尾/分位數。
2. **TTL 衰減**：觀眾流動快，一次性 override 不得永久污染群參數。
3. **宣告 / 觀察分源**：使用者「說的」（可玩梗、反串）與「做的」（持續行為）必須分開，宣告可即時高權重，觀察只能慢速低權重且標
   `source=observed`。

**事件視窗聚合**（彈幕 10–100 條/秒不得逐條觸發轉移）同屬 `group`
啟用前必備：進 buffer → 按 tick 聚合成統計量 →
AL 只看摘要。這也自動守住 §1.2 第 2 條。

## 8. 事件與聚合

- **事件類型**：互動結果、使用者反饋、記憶固化請求、狀態觀測（bio/heartbeat 採樣）、修正事件。
- **寫路徑**：`submit_event(type, payload)` → 聚合（視窗/tick 對齊）→ 轉移函數。
- **修正留痕**：任何 `invariant` / `slow` 欄位的大幅修正記為 `epoch`
  —— 每次大修正是一次身分事件，必須可回放（「剛才那波為什麼人設崩了」是運營問題，不是哲學問題）。
- **原始內容不進 AL**：彈幕、對話原文歸記憶／表現層；AL 只取統計摘要。

## 11. 效應器介面：反射、協調、意圖（本能不經過皮層）

### 11.1 要防的錯誤路徑

AL 判定「現在身體該是什麼樣」之後，若路徑寫成
**`AL → 塞進 prompt → AI 決定身體怎麼動`**，就是錯的：等於呼吸時要皮層想著每一束肌肉。今日已有這個病的症狀：大量「行為調整」是以
`routing_mode` / `response_style`
注入 prompt，讓模型自己表演身體 —— 身體成了說話的一部分。

### 11.2 三條路徑（對應神經系統，各有延遲預算與失效策略）

| 路徑     | 生物對應                    | 誰決定                                     | 延遲     | 例子                                       |
| -------- | --------------------------- | ------------------------------------------ | -------- | ------------------------------------------ |
| **反射** | 脊髓反射弧 + 腦幹節律發生器 | AL 狀態 → 固定模式，**不經 LLM**           | ms 級    | 喚醒度低→關高耗能模態、idle/眨眼、驚嚇、癢 |
| **協調** | 小腦                        | 不發起意圖，只管時序、平滑、誤差修正、學習 | ms～百ms | 表情混合曲線、動作時序、節奏、依反饋修正   |
| **意圖** | 皮層 ＝ AI 引擎             | 說什麼、調什麼工具、下一步做什麼           | 百ms～秒 | 回答內容、工具選擇、任務規劃               |

**器官要校正一下**：呼吸的節律來自**延髓/腦幹**，不是小腦；**小腦管協調與時序、不發起意圖**；**反射弧在脊髓，根本不進腦**。三者都不經過皮層 —— 而這個區分對設計有實際影響，因為三者是**三種不同機制**：混成一條路就沒辦法分別給延遲預算、分別設失效策略（反射失敗可忽略並回報，意圖失敗要重試）。

### 11.3 三條規則

1. **本能路徑不得經過 LLM / router**：`ALState → 效應器命令 → broadcast`
   是**資料流**，不是推理流。門禁：效應器模組不得 import `services.llm.*` /
   `ai.*`（不變式 I10）。
2. **皮層設模式，不逐幀指揮肌肉**：AI 可以設定意圖與模式（「接下來安靜一點」→ 由 AL 轉成參數與身體命令），但**不直接輸出逐幀身體命令**。
3. **反射必須回報**：本能動過身體後，以事件形式寫回快照（§8
   `submit_event`），否則 AI 對「身體剛才做了什麼」無知 —— 這是意圖與身體脫鉤的另一種形式。

### 16.1 Q6 驗證記錄（2026-10-25，已結案）

**結論：前端 Live2D 渲染原本不正常，根因已定位並修復，D7 的前提成立。**

根因為三層疊加，全部落在 `packages/shared-js/js/live2d-cubism-wrapper.js`（經
`scripts/sync_shared_js.py` 同步至 web viewer 與 Electron 兩份副本）：

1. **shader Y 翻轉反了**：vertex shader 寫
   `gl_Position = vec4(pos.x, -pos.y, ...)`，而 CubismCore 輸出與 clip 空間同為 y-up。官方 framework
   `src/rendering/cubismshader_webgl.ts` 的
   `gl_Position = u_matrix * a_position` 同樣不做翻轉。已移除 `-pos.y`。
2. **transform 硬編碼**：舊碼寫死 `scaleY=2.0`（註解稱 Core 輸出
   `[-0.5, 0.5]`，實測此模型 y∈[-0.774,
   0.725]），造成上下裁切且模型只佔畫布約 40% 寬。改為掃描 drawable 頂點求 bbox、等比 fit（margin
   0.92、 `scaleX/scaleY = canvasH/canvasW`）且**每幀依當前 canvas 尺寸重算**
   （舊碼連 `resize()` 都不重算）。另修 `canvasinfo.OriginX` →
   `CanvasOriginX/CanvasOriginY`（舊碼永遠讀到 undefined）。
3. **貼圖 V 方向未翻轉**：Cubism UV 約定 `v=0`
   對應圖像**底部**（GL 約定），而 WebGL 未設 `UNPACK_FLIP_Y_WEBGL` 時 `t=0`
   取圖像第一列（頂部）——整張圖集在部件內上下鏡像，是「五官與頭髮碎裂錯位」的主因。
   `loadTexture()` 已補 `pixelStorei(gl.UNPACK_FLIP_Y_WEBGL, true)`。

驗證證據鏈（純本地、離線 + headless Chromium CDP，未連任何外部服務）：

- **資料無誤**：離線探針（Node 載入 CubismCore 5.1.0 + moc3）與 live
  dump 逐頂點一致——66 個 drawable、bbox
  `x∈[-0.36,0.348] y∈[-0.774,0.725]`、30 個參數全為預設值、索引無越界。
- **GPU = 程式碼**：修復前實拍與「同 transform 的離線幾何」逐像素比對，live-only
  ink = **14 px / 0.00%**
  → 碎裂不來自 renderer 邏輯或 GPU，只可能來自 transform 公式。
- **修復後實拍 = 正確參考**：離線渲染「不翻幾何 + 翻 V」產出的正確畫面與修復後實拍平均 RGB 差
  **2.74/255（≈1%）**，差異集中在抗鋸齒邊緣與左上角頁面 UI 疊層；console 無任何渲染／shader 錯誤。
- **殘餘 console error 全屬環境性**：browser 環境無
  `window.electronAPI.settings.getAll`、backend
  :8000 未啟動導致的WebSocket 重連——與渲染無關。

**已知未修（照實記）**：畫布高 720px，於 657px 高的視窗（本次 headless 視窗）下緣超出可視區，腳部被視窗截掉；這是頁面佈局與視窗尺寸問題，非渲染缺陷，一般視窗夠大時不復現，未納入本次修復範圍。
