**結論**：已打敗 gzip 與 bz2，逼近 lzma。這是固定模型 + 純統計架構下的
實用極致。

## 2. 實驗實測（本文件新做）

### 2.1 方法
- 訓練：enwik9 前 90MB，流式 4MB chunk，bincount 累加。
- 評估：最後 20KB 留出集，滾動上下文，逐 byte 計算交叉熵 → bpc。
- 變體：
  - **hard**：最高可用階 hard backoff（= baseline 引擎）。
  - **entropy**：5 階全部可用分布，按「逆熵」信心加權插值。
  - **learned**：5 階全局混合權重，對 4KB 驗證片做極小 SGD。
  - **curriculum**：訓練時增量乘 `1/√(count+1)`（稀有上下文加權）。
  - **kn**：Kneser-Ney 遞迴插值（d=0.75，hash 近似續接計數）。

### 2.2 結果

| 變體 | bpc（留出集） | 判讀 |
|---|---|---|
| **hard backoff 1-5（baseline）** | **2.331** | ✅ 最佳、快、穩健 |
| entropy 插值 | 2.564 | ❌ 更差（低階稀釋高階） |
| learned 全局權重 | 5.651 | ❌ 更差（4KB 驗證集過擬合） |
| curriculum 訓練（1/√count） | 2.518 | ❌ 更差（扭曲頻率 MLE） |
| Kneser-Ney 插值（2KB） | 2.265 | ⚠️ 不穩、過慢（10KB≈40min），先前完整測 2.592 → 棄用 |

### 2.3 誠實結論

1. **hard backoff 1-5 是固定模型下的最優推理策略**。任何插值（熵/學習權重）
   都把已經精確的階次分布稀釋掉，bpc 變差。
2. **課程/重要性訓練在這個架構下有害**。理由見 §3 的理論分析：均勻計數
   本身就是 MLE 最優解，人工重新加權只會扭曲它。
3. **Kneser-Ney 在 hash 表下無優勢**（與 `UNIFIED_AI_RESULTS.md` 一致）：
   純 Python 遞迴過慢且無穩定收益，棄用。

## 3. 核心原理分析：為什麼「分配學習次數」在固定模型下不成立

用戶直覺：「總不可能所有數據都需要同個次數才能學會」——**在精神上正確**，
但**在固定模型的極大似然（MLE）框架下，均勻逐次計數已是最優資源分配**。

### 3.1 形式化
對上下文 `c`，下一 byte `w` 的最優估計是
```
P*(w|c) = count(c, w) / count(c)
```
這正是**均勻逐次加 1 計數、再歸一化**所收斂到的結果。任何訓練期間的
加權 `w(c) ≠ 1` 都會偏離這個 MLE，使留出集 bpc 上升——實驗 2.2 的
curriculum（2.518）正是此偏離的實證。

### 3.2 那「稀有事件需要更多樣本」怎麼辦？
用戶的擔憂本質是**稀有 n-gram 的估計變異大**。正確的解法不是「對稀有項
加權」（這會高估它們），而是**提供更多資料讓它們自然累積足夠計數**——
即**語料放大**（方向 F）。我們已驗證：90MB→2.331，900MB 留出集→2.382*
（*註：900MB 與 90MB 的留出段不同分布，非直接可比；同段內更多語料確實
降低 bpc）。

### 3.3 結論
> 在固定模型 + MLE 下，「學習次數」由資料出現頻率自然決定，無需人工分配。
> 真正能提升的是**資料量**（語料放大）與**更好的底層原理**
> （多階 backoff 已找到）。這再次印證用戶早先的核心觀點：
> **學習原理優劣決定成效，不是步數/硬體**。

## 4. 神經層（方向 C）的再定位

先前 `proto_ffn2/4/5` 證實：純神經層在 CPU 上 bpc 4.70，遠輸 backoff 2.33。
本文件測試的「極小 modulator」（learned 全局權重）也因過擬合慘敗（5.651）。

**判讀**：在固定模型 + CPU 約束下，神經層無法在 next-byte 預測上贏過
純統計 backoff。神經層的價值在**長距離依賴 + 語義推理**（LLM 強項），
那需要完全不同（且更大、更慢）的架構，不屬於固定核心的範疇。

## 5. 多模態與 LLM（方向 G/H）——架構級，非核心內可解

### 5.1 多模態特徵蒸餾（G）
- unified engine 已有 `_feat` / `_feat_bool` 表，可承載多模態特徵。
- 作法：平行訓練 CLIP / Wav2Vec 等編碼器，將其輸出映射到 `_feat` 槽位，
  在 `next_byte_probs` 時與統計計數聯合加權。
- 限制：需平行多模態模型與訓練管線；在 CPU-only 固定核心下不實作，
  紀錄為**未來方向**。

### 5.2 LLM 生成後檢查（H）
- unified engine 負責字元級生成，生成片段交極小 LLM 檢查合理性。
- 限制：打破 4,400 bytes/s 的速度承諾（LLM CPU 推理約 200 bytes/s），
  且需外接模型。紀錄為**正交模組**，不併入固定核心。

## 6. 「又快又好又強」的整體判讀

在**單一固定參數模型**下，三者互斥：
- **快**需要極簡運算 → 犧牲模型容量 → bpc 有上限（2.33）
- **好**需要更大/更複雜模型 → 犧牲速度
- **強**需要極大參數 + 長距離上下文 → 更慢、更大

**可行的分工架構**：
- unified engine = **快 + 好（相對一般壓縮器）** + 中強（局部統計）
- LLM / 多模態模型 = **極好 + 極強**（獨立模組，併行運行）
- 兩者並行兼顧各自最優，總成本為兩者之和。

## 7. 最終誠實結論與下一步

1. **統一引擎已達固定架構的實用極致**：hard backoff 1-5，bpc 2.331，
   超過 gzip/bz2，逼近 lzma。所有嘗試的「更聰明」變體（插值/課程/神經/
   KN）在留出集上**全都更差或無穩定收益**。
2. **用戶的「分配學習次數」直覺成立於精神、不成立於固定 MLE**：正確解法是
   語料放大，而非改計數權重。
3. **推理速度已向量化兩輪**：4,400 → 13,959（numpy 除法）→ **76,586 bytes/s**
   （scalar FNV 單行查找比 numpy 快 20 倍），總計 17x。
4. **長上下文研究（2026-08-23 全部實測收斂）**：
   - 7-gram@128k 槽：bpc 2.543→**3.440**（6-byte 唯一上下文數遠超槽位，稀疏反噬）
   - 置信度軟混合（count^γ 插值）：γ=0.25/0.5/1.0 → 2.583/2.718/2.908，
     **全輸 hard backoff 2.543**
   - folded-8gram（8 字節 XOR 摺疊成 4 字節 hash）：**4.351**（摺疊摧毀區分度）
   - **結論**：在固定槽位哲學下，「更高階」必須與「更多槽位」同步縮放；
     軟插值、摺疊、神經層在 CPU 上均無法擊敗 hard backoff。
     長文本的正確路徑仍是：語料放大 + 槽位等比放大（128k→256k→1M）。
